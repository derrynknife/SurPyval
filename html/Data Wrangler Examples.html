Data Wrangling Examples

Every SurPyval fitter takes data in the same form: values x, censoring flags c, counts n and truncation t (or tl and tr), described in Conventions. Data rarely arrives that way. It comes as a list of failures and a list of survivors, as text with “+” marks, as a spreadsheet of install and removal dates, or as counts found at each inspection. This page shows how to get from each of these to something fit() accepts. The tool for it is SurpyvalData: its constructors read each common layout, it validates the data exactly as the fitters do, and the parametric, non-parametric and regression fit methods take one in place of the arrays. The general recipe is always the same: decide, for each item, what is known about its value (exact, above a value, below a value, or between two values) and whether it could have been missed altogether (truncation), then write that down as x, c, n and t.

Let’s say we have a list of failures and a list of right censored (suspended) values. SurpyvalData.from_observations takes a list of each kind of observation, and the fitters take what it returns:

import surpyval as surv
from surpyval import SurpyvalData

# Failure data
f = [2, 3, 4, 5, 6, 7, 8, 8, 9]
# 'suspended' or right censored data
s = [1, 2, 10]

data = SurpyvalData.from_observations(observed=f, right_censored=s)
print(data.x, data.c, data.n)

model = surv.Weibull.fit(data)
print(model)

A fit given a SurpyvalData takes everything from it – values, flags, counts, truncation and, for a regression, the covariates Z – so it refuses c, n, t (and the rest) given alongside it. data.to_xcnt() gives the arrays themselves, x, c, n, t, where a function of your own needs them.

# Failure data

# left censored data
l = [7, 8, 9]

)
print(data.x, data.c, data.n)

model = surv.Weibull.fit(data)

Another common type of data that is provided is in a simple text list with “+” indicating that the observation was censored at that point. Using some simple python list comprehensions can help.

# Example provided data
data = "1, 2, 3+, 5, 6, 8, 10, 3+, 5+"

f = [float(x) for x in data.split(',') if "+" not in x]
s = [float(x[0:-1]) for x in data.split(',') if "+" in x]

data = SurpyvalData.from_observations(observed=f, right_censored=s)

model = surv.Weibull.fit(data)

data = "1, 2, 3+, 5, 6, 8, 10, 3+, 5+, 15-, 16-, 17-"

The notation in surpyval.utils.notation reads that text directly, and gives a way of writing small datasets in code the way you would describe them. Observations.parse takes entries separated by commas, semicolons or new lines: 10 failed at 10, 20+ still running at 20, <3 or 3- failed before 3, [5, 10] failed between 5 and 10, and 3*10 three units alike:

from surpyval.utils.notation import Observations

data = Observations.parse("1, 2, 3+, 5, 6, 8, 10, 3+, 5+, 15-, 16-, 17-")
model = surv.Weibull.fit(data.surpyval_data())
model

In code, each observation is one object: O (failed at), RC (still running at), LC (failed before) and IC (failed between). n * obs is n units alike, and obs / Truncation(tl, tr) says the unit was only observed within (tl, tr] (late entry at tl); dividing a whole Observations by a Truncation gives every observation without a window of its own that window. An observation outside its window is refused, and the printout reads as words:

from surpyval.utils.notation import IC, LC, RC, O, Truncation

data = Observations([
    3 * O(10), RC(20), LC(3),
    IC(5, 10) / Truncation(0, 40),
])
print(data)
print(data.xcnt())

xcnt() gives the arrays (one row per observation, tl/tr of -inf/inf where there is no truncation) and surpyval_data() the SurpyvalData every fitter takes; a fitter also takes the Observations as it is. The rules are those of SurpyvalData, checked when each observation is built: a count is a whole number, a time is finite, a point lies in its window (tl, tr] (a suspension strictly before tr), an interval lies inside it (tl <= lower, upper <= tr), and an interval open at one end is one-sided censoring (IC(5, inf) is RC(5)).

In text, a window follows its entry after a bar, 12 | (2, 50] (inf for an open side), and text() writes the observations back as text that parse reads as the same ones. SurpyvalData.from_notation takes the text or the Observations, and data.to_notation() goes back:

data = Observations.parse("3*10, 20+, [5, 10] | (2, 40], 12 | (2, inf]", unit="hours")
model = surv.Weibull.fit(data)
print(model.unit)
back = surv.SurpyvalData.from_notation(data).to_notation()
print(back.text())

hours
[5, 10] | (2, 40], 3*10, 12 | (2, inf], 20+

Each observation can also say what failed and describe its unit: event_type= (a failure mode or cause, for the competing-risks models; never on a suspension) and covariates={name: value}, which become the data’s event types e and its named covariates Z. Every observation needs the same covariate names, and a set that does not is refused, saying which names are missing. The text form leaves these out, so it stays readable; they stay in Python:

obs = Observations([
    O(410, event_type="bearing", covariates={"temp": 60}),
    O(520, event_type="seal", covariates={"temp": 75}),
    2 * RC(800, covariates={"temp": 60}),
])
data = obs.surpyval_data()
print(data.covariate_names, data.Z.ravel(), data.e)
print(obs.text())

['temp'] [60. 75. 60.] ['bearing' 'seal' None]
410, 520, 2*800+

A unit watched over several events, a repairable item, is an Item: its id, then its events. RC is the end of watching (its age when last seen; at most one, after every event), Item(...) / Truncation(tl) is late entry, 3 * O(120) is three failures at the same age, IC(a, b) a failure found between two inspections, and O(800, terminal=True) the event that ended the history for good (a = 1: scrapped or written off). The item’s fixed covariates go on the item, covariates={...}. Items collects them, and surpyval_data() gives the SurpyvalData with each row’s unit i and terminal flag a, the form every recurrent fitter takes (and takes the Items as it is):

from surpyval.utils.notation import Item, Items

fleet = Items([
    Item("P1", O(120), O(310), IC(400, 450), RC(1000)) / Truncation(0),
    Item("P2", 3 * O(200), O(900, terminal=True)),
], unit="hours")
print(fleet.surpyval_data())
surv.recurrent.CrowAMSAA.fit(fleet)

A history can be written as one line of text, its id, a colon and its events in the same grammar, with the item’s window last after a bar; text() writes it back (covariates, event types, terminal flags and readings stay in Python):

fleet = Items.parse("""
    P1: 120, 310, [400, 450], 1000+ | (0, inf]
    P2: 3*200, 900
""")
print(fleet.text())

P1: 120, 310, [400, 450], 1000+ | (0, inf]
P2: 3*200, 900

Readings taken on an item over its life go in readings: {name: {age: value}} for named measurements, or one {age: value} series, which the joint models read as their markers. They become the data’s Measurements. Covariates that change over the item’s life are given as a StepSchedule (or CovariatePath) in time_varying_covariates, and passed through as they are: the fits expand them into stretches themselves.

from surpyval import StepSchedule

pumps = Items([
    Item("A", O(100), readings={"vibration": {0: 1.2, 50: 1.9}},
         time_varying_covariates=StepSchedule.from_changepoints([0, 50], [0.0, 1.0])),
    Item("B", RC(120), readings={"vibration": {0: 1.0, 60: 1.1}},
         time_varying_covariates=StepSchedule.from_changepoints([0], [0.0])),
])
data = pumps.surpyval_data()
print(data.m)
print(data.time_varying_covariates)

Measurements: vibration - 2 units, 4 readings
{'A': StepSchedule.from_changepoints([0.0, 50.0], [[0.0], [1.0]]), 'B': StepSchedule.from_changepoints([0.0], [[0.0]])}

SurpyvalData with i is the form for several rows per unit; EventHistoryData is being phased out, and fleet.event_history_data() gives one only for code that still needs it.

Surpyval also offers the ability to use a pandas DataFrame as an input to every fitter. All you need to do is tell fit_from_df which columns to look at for x, c, n, and the truncation, tl and tr. Columns for c, n, tl and tr are optional, and tl and tr can also be given as a single number that applies to every row. Further, if you have interval censored data you can use the ‘xl’ and ‘xr’ column names instead. Any other fit option is passed straight to fit, and the model is the one fit gives on the same arrays. The parametric distributions (Weibull.fit_from_df), the non-parametric estimators (KaplanMeier.fit_from_df), RoystonParmar and MixtureModel take the arguments below; the regression, competing-risks and recurrent-event fitters name their columns x_col, c_col, Z_cols, e_col, i_col, … (see Conventions).

import pandas as pd

xr = [2, 4, 6, 8, 10]
xl = [1, 2, 3, 4, 5]
df = pd.DataFrame({'xl' : xl, 'xr' : xr})

model = surv.Weibull.fit_from_df(df, xl_col='xl', xr_col='xr')
print(model)

If you have mixed interval and observed or censored data, the two columns can still describe every row, provided no c column is given: a row with the same value in both columns is an exact observation, a row whose xr is infinite is right censored at xl, and a row whose xl is minus infinity is left censored at xr. This is exactly the shape of inspection data recorded as “last seen working” and “first seen failed”:

import numpy as np

df = pd.DataFrame({
    'last_ok':      [-np.inf, 150, 300, 420,    500, 610],
    'first_failed': [200,     150, 380, np.inf, 500, np.inf],
})
# row 0: failed before the first inspection at 200 -> left censored
# rows 1 and 4: failure time known exactly         -> observed
# row 2: failed between inspections at 300 and 380 -> interval censored
# rows 3 and 5: never seen failed                  -> right censored
data = SurpyvalData(xl=df['last_ok'], xr=df['first_failed'])
print(data.c)

model = surv.Weibull.fit_from_df(
    df, xl_col='last_ok', xr_col='first_failed'
)
print(model.params)

[ 0 -1  2  1  0  1]
[498.97122045   1.43729139]

(SurpyvalData validates its input exactly as every fitter does; building one yourself is a quick way to check how SurPyval has read your data. Its rows are sorted, so the flags come back in order of time.)

To see the data itself, data.plot_lifetimes() draws one line for each unit (a swimmer plot): a filled circle where it failed, an open triangle where it was still running (right censored) or had already failed (left censored), a bracket over an interval, and the line starting where the unit came under observation (late entry). A row standing for several items is labelled with its count, an item’s several rows share a line, event types take colours, and max_rows (100 by default) limits a large dataset, saying how many lines were left out. It returns the Axes.

data = SurpyvalData.from_observations(
    observed=[3, 5],
    right_censored=[8],
    left_censored=[2],
    interval_censored=[[4, 6]],
    observed_left_truncation=[0, 1],
)
ax = data.plot_lifetimes()

One record per item

When each item’s record carries more than a time and a flag (its own observation window, what failed, its covariates), describe it with an ItemLifetime and build the data from the list. How many identical items each one stands for goes in counts:

from surpyval import ItemLifetime

items = [
    ItemLifetime("B7", observed=1820, covariates=[1.0]),
    ItemLifetime("B8", right_censored=2400, covariates=[0.0]),
    ItemLifetime("B9", interval_censored=[1000, 1500], covariates=[1.0]),
    ItemLifetime("B10", observed=950, left_truncation=200, covariates=[0.0]),
]
data = SurpyvalData.from_items(items, counts=[3, 40, 2, 5])
print(data.n)
surv.Weibull.fit(data.without("covariates")).params

[ 3 40  2  5]

array([6.12713963e+03, 1.57422904e+00])

Records are updated as items age, each update giving a new, checked record (the old one is left as it was), and copied for a new item with clone. A record is fixed once made, so it is always one that passed its checks:

b8 = ItemLifetime("B8", right_censored=2400)
print(b8.extend(2800))            # still running at 2800
print(b8.fail(2650, "spall"))     # failed at 2650
print(b8.found_failed(3000))      # found failed at the 3000 inspection
print(b8.clone("B11"))            # the same record for another item

from surpyval import ItemHistory

pump = ItemHistory("P1", observed=[420], right_censored=600)
print(pump.add_failure(700))      # failed again at 700

ItemLifetime('B8', right_censored=2800.0)
ItemLifetime('B8', observed=2650.0, event_type='spall')
ItemLifetime('B8', interval_censored=[2400.0, 3000.0])
ItemLifetime('B11', right_censored=2400.0)
ItemHistory('P1', observed=[420.0, 700.0], right_censored=700.0)

Every check names the item, and data.to_items() gives the items back (SurpyvalData.from_items(data.to_items(), counts=data.n) is the same data). A plain fit of data that holds more than a plain fit takes (covariates, event types) is of data.without("covariates", "event_types"), which keeps everything else – B10’s late entry here – rather than of records rebuilt by hand. An item’s event_type goes to the competing-risks fitters (CompetingRisks.fit(data)), and its step time_varying_covariates ({age: values} or a StepSchedule) to a regression’s fit_tvc: WeibullPH.fit(data) splits each item’s life where its covariates step. A continuously varying CovariatePath is kept with the data but not fitted yet (#908).

The fitted model predicts for an item from its own covariates, model.sf_tvc(times, item), with no schedule to build by hand: the item’s fixed covariates and its time-varying ones are lined up as the fit took them. Datasets from several sources join through their records, SurpyvalData.from_items(site_a.to_items() + site_b.to_items(), counts=[*site_a.n, *site_b.n]), which refuses an item id found in both.

from surpyval import StepSchedule

stress = StepSchedule.from_changepoints([0, 500], [[0.0], [1.0]])
rng = np.random.default_rng(1)
life = rng.weibull(2.0, 60) * 900
items = [
    ItemLifetime(k, observed=t, time_varying_covariates=stress)
    for k, t in enumerate(life)
]
surv.WeibullPH.fit(SurpyvalData.from_items(items)).params

array([9.75340851e+02, 1.76396302e+00, 1.38954081e-01])

Covariates given by name, covariates={"age": 54, "arm": 1}, are named in the data (covariate_names) and in the fitted model, whose coefficients take the names; an item’s names may come in any order:

rng = np.random.default_rng(3)
trial = []
for k in range(80):
    arm, age = k % 2, float(rng.uniform(40, 70))
    t = rng.weibull(1.5) * 1000 * np.exp(-0.6 * arm)
    trial.append(ItemLifetime(k, observed=t, covariates={"arm": arm, "age": age}))
data = SurpyvalData.from_items(trial)
print(data.covariate_names)
surv.WeibullPH.fit(data).params

['arm', 'age']

array([1.46281962e+03, 1.57856629e+00, 8.01973868e-01, 9.45132342e-03])

From a DataFrame

Most data arrives as a table with one row per item: its id, its age, a column saying whether it failed, what failed, and its covariates. SurpyvalData.from_dataframe reads it, naming the columns as every DataFrame entry point does (x_col, c_col, … the fit argument with _col); a spreadsheet’s status column, 1 or True where the item failed, is event_col (the opposite coding of c):

fleet_df = pd.DataFrame({
    "unit":   ["P1", "P2", "P3", "P4", "P5"],
    "hours":  [820, 1450, 2000, 1100, 1700],
    "failed": [True, True, False, True, False],
    "mode":   ["seal", "bearing", None, "seal", None],
    "site":   [1, 0, 1, 0, 0],
    "load":   [0.8, 0.5, 0.4, 0.9, 0.6],
})
fleet = SurpyvalData.from_dataframe(
    fleet_df, i_col="unit", x_col="hours", event_col="failed",
    e_col="mode", Z_cols=["site", "load"],
)
print(fleet.summary())
print(fleet.item("P3"))

inspections = pd.DataFrame({

data = SurpyvalData.from_dataframe(

One dataset, several analyses

A dataset built with covariates and failure modes (the fleet above) is refused by a fit that takes neither, rather than fitted as if they were not there. Reshape it for the analysis instead; each operation returns a new dataset:

everything = fleet.without("covariates", "event_types")   # a plain fit
seals = fleet.for_event_type("seal").without("covariates")  # one mode
by_load = fleet.with_covariates(["load"])   # a regression on load alone
site1 = fleet.select(where=lambda item: item.covariate("site") == 1)
first_1500 = fleet.censor_at(1500)   # as seen at the end of a study
print(surv.Weibull.fit(everything).params)
print(seals.summary())

[1845.64603147    2.47017653]
SurpyvalData: 5 items, 5 rows (with item ids)
  outcomes: 2 observed, 3 right censored

Updating a dataset as items age

A fleet’s data is refreshed as the months pass: some items fail, the rest run on, new ones are installed. The records’ update methods (fail, found_failed, extend, add_failure) give the new records, and update takes them back into the dataset – a record whose id is in the data replaces that item’s, a new id is added – while extend_running moves every item still running on to the age it was last seen, and drop removes items. Counts, covariates, event types, attributes and the unit carry through:

month_end = {"P1": 900, "P2": 1500, "P3": 2100, "P4": 1200, "P5": 1800}
refreshed = fleet.update([
    fleet.item("P3").fail(2050, "bearing"),           # failed this month
    ItemLifetime("P6", right_censored=90, covariates={"site": 1, "load": 0.7}),
]).extend_running(lambda item: month_end.get(item.id, 90))
print(refreshed.summary())

Combining every input type in one fit

The real strength of the surpyval format is that these ingredients — exact, left-, right- and interval-censoring, repeat counts, and truncation — compose freely in a single fit call. Each row of x carries its own censoring flag c and count n; a row is interval-censored simply by giving it two values [lower, upper]:

x = [10, 12, [15, 20], 22, 25, 30]   # a [lo, hi] row is interval-censored
c = [0,  1,   2,       -1,  0,  1]    # observed, right, interval, left, ...
n = [5,  3,   2,        1,  4,  2]    # each row repeated n times
model = surv.Weibull.fit(x=x, c=c, n=n, tl=5)   # all left-truncated at 5

Combining, comparing, rescaling and resampling

Two batches of data become one with SurpyvalData.concat([a, b, ...]) or a + b. Everything each row has comes across (counts, weights, event types, truncation, attributes, readings), and the rows are sorted as the constructor sorts them. Datasets in different units, with different covariates, or sharing an item id are refused, each saying what to do: an id is one item, so rename the ids first where two sources used the same ones. == compares two datasets exactly and equals(other, rtol=...) to a tolerance. to_dataframe() and from_dataframe() with no column arguments are a round trip. rescale_time(factor, unit=...) puts the data on another clock (24 from hours to days, 0.25 for a quarter duty cycle), as the model method of the same name does, so a fit of the rescaled data is the rescaled fit. resample(random_state=...) draws the units with replacement for a bootstrap: a row counted n is n units, and an item’s rows move together.

From dates to durations

Field data often arrives as a table of dates: when each unit was installed, when (if ever) it was removed, and why. Two decisions turn this into survival data:

  • The value is the time in service: removal date minus install date, or, for units still in service, the end of the study minus the install date.

  • The flag is 0 only when the unit was removed because it failed. A unit still in service is right censored, and so is a unit removed for any other reason (a preventive replacement, an upgrade, a sale): all we know is that it had not failed by then.

log = pd.DataFrame({
    "unit":      ["A", "B", "C", "D", "E", "F"],
    "installed": ["2020-01-10", "2020-03-01", "2020-06-15",
                  "2021-01-05", "2021-02-20", "2021-07-01"],

                  None, "2022-03-01", "2022-02-14"],
    "reason":    ["failure", None, "failure",
                  None, "preventive", "failure"],
})
log["installed"] = pd.to_datetime(log["installed"])
log["removed"] = pd.to_datetime(log["removed"])

A common mistake is to count the preventive replacement of unit E as a failure. It was not one, and counting it as one makes the item look less reliable than it is. Another is to leave units B and D out because they “have no failure date”: they are the survivors, and they carry most of the information about how long the units last.

If units only came under observation some time after they were installed (for example, records only start at the date a database was set up), each unit’s age on that date is its left truncation value, tl.

Inspection data needs one more step. A failure found at the first inspection after the records begin is interval censored from the unit’s last good inspection, xl, which came before the records begin. Its age when the records begin is then not its tl: the unit is in the data because its failure was detected after that date, and all that is known is that it was working at its last good inspection, so that inspection is its left truncation time (tl = xl). Given the age at the start of the records instead, the fit refuses the row (an interval cannot start below its own left truncation time) and the message says this. Do not repair it by moving xl up to tl: that claims the unit was seen working when it was not, and biases the fit.

inspections = pd.DataFrame({
    "last_ok":   [80.0, 150.0, 210.0, 260.0],   # age at the last good inspection
    "found":     [120.0, 190.0, 250.0, 300.0],  # age when found failed
    "age_at_start": [100.0, 100.0, 100.0, 100.0],
})
# Found failed at the first inspection after the records began
straddles = inspections["last_ok"] < inspections["age_at_start"]
inspections["tl"] = np.where(straddles, inspections["last_ok"],

Counts found at inspections

When units are only checked periodically, the data is a count of failures found at each inspection: a life table. Each count is interval censored between the previous inspection and the one at which it was found, and the units still working at the last inspection are right censored there. The counts go in n:

inspections = [0, 100, 200, 300, 400]
found_failed = [3, 7, 9, 4]        # failures found at 100, 200, 300, 400
still_working = 12                 # at the last inspection

x = [[lo, hi] for lo, hi in zip(inspections[:-1], inspections[1:])]
x = x + [inspections[-1]]
c = [2] * len(found_failed) + [1]
n = found_failed + [still_working]
print(x)

life_table = surv.Weibull.fit(x=x, c=c, n=n)
print(life_table.params)
print(surv.Turnbull.fit(x=x, c=c, n=n).sf(inspections[1:]))

[376.6627073    1.69651666]

from_observations reads the table as it is written, with a count for each item (an interval in which nothing was found can stay in, counted 0):

data = SurpyvalData.from_observations(
    interval_censored=[[0, 100], [100, 200], [200, 300], [300, 400]],
    interval_censored_counts=[3, 7, 9, 4],
    right_censored=[400],
    right_censored_counts=12,
)
print(surv.Weibull.fit(data).params)

[376.6627073    1.69651666]

Resist the temptation to put each failure at the inspection time at which it was found (or at the midpoint of the interval). Doing so invents precision the data does not have, and pushes every failure later (or to an arbitrary point) within its interval. Interval censoring uses exactly what was observed. Turnbull, the non-parametric estimator that handles interval censoring, is a good check on the parametric fit.

Recurrent events from a maintenance log

For repairable items, each item can fail many times. The recurrent event models take one row per event, with the item identifier i, the cumulative age of the item at the event in x, and one extra row per item, flagged c = 1, giving how far that item has been observed. A maintenance log with hour-meter readings at each failure, plus each machine’s current reading, is exactly this:

from surpyval.recurrent import NonParametricCounting

failures = pd.DataFrame({"machine":    ["M1", "M1", "M1", "M2", "M2", "M3"],
                         "hour_meter": [420, 1310, 2050, 980, 2400, 1720]})
current = pd.DataFrame({"machine":    ["M1", "M2", "M3"],
                        "hour_meter": [2600, 2900, 3100]})

events = pd.concat([failures.assign(c=0), current.assign(c=1)],
                   ignore_index=True)

mcf = NonParametricCounting.fit(x=events["hour_meter"],
                                i=events["machine"],
                                c=events["c"])
print(mcf.mcf([1000, 2000, 2600]))

[0.66666667 1.33333333 2.        ]

The same log, written as each machine’s history keyed by its id, is read by EventHistoryData.from_histories: observed holds each machine’s age at its failures and right_censored its current reading. Every recurrent fit takes the result in place of the arrays:

from surpyval import EventHistoryData

data = EventHistoryData.from_histories(
    observed={"M1": [420, 1310, 2050], "M2": [980, 2400], "M3": [1720]},
    right_censored={"M1": 2600, "M2": 2900, "M3": 3100},
)
print(NonParametricCounting.fit(data).mcf([1000, 2000, 2600]))

[0.66666667 1.33333333 2.        ]

A machine left out of right_censored is taken to have been observed until its last failure. left_truncation (the age at which a machine came under observation) and covariates (one row per machine, for the proportional intensity models) are keyed the same way, and gaps=True reads the times between failures, adding them up within each machine. data.to_histories() gives the dictionaries back.

The same histories give lifetime data for the lifetime models: to_first_events() is each machine’s time to its first failure (right censored where it has none), and to_gaps() the times between its failures, each repair taken to make it as good as new, its last gap right censored at the end of its observation. Both keep each machine’s delayed entry, covariates and ids (("M1", 2) for M1’s second gap):

print(data.to_first_events().x)

Every check names the item and says what is wrong with its history, and data.to_items() gives the items back. Two kinds of history are kept with the data for the models that will use them, and refused by every fit until then:

  • time_varying_covariates (#905): {age: values}, a StepSchedule or a continuously varying CovariatePath.

  • The item’s path through states (#887), recorded like its failures: an initial_state, changes seen as they happened (observed_states={age: state}), changes between two inspections (interval_censored_states= [[lower, upper, state]]) and a state already reached at the first look (left_censored_states).

markers (repeated measurements, #891) are reserved for joint models of histories; a lifetime’s record, ItemLifetime, takes them now (see Joint Models).

The conversions are not all lossless, and it pays to know where they drop information:

  • to_xrd is exact for observed and right censored data without right truncation; left truncation is allowed, and is used to build the risk sets. Left or interval censored values have no single time at which to count a death, so for those (or for right truncated data) it fits the Turnbull estimator and returns its numbers at risk and deaths, which can be fractional.

  • from_xrd cannot recover left truncation, and raises an error if the risk set ever grows from one time to the next. xrd data must list each time once; rows given out of order are sorted by time (keeping their r and d), and a time listed twice is an error. More deaths than items at risk is an error too.

  • to_observations and from_observations lose nothing: SurpyvalData.from_observations(**data.to_observations()) is the same data, counts, truncation and covariates included.

Observed and right censored data folds into the xrd form, the count at risk and the number of deaths at each distinct time:

x, c, n = [1, 2, 3, 4, 5], [0, 0, 1, 0, 1], [2, 1, 1, 3, 1]
times, at_risk, deaths = SurpyvalData(x, c, n).to_xrd()
print("times  :", times)
print("at risk:", at_risk)
print("deaths :", deaths)

times  : [1. 2. 3. 4. 5.]
at risk: [8 6 5 4 1]
deaths : [2 1 0 3 0]

Going back with from_xrd recovers the same rows here. The number censored at each time is what is left of the risk set after the deaths, r[j] - d[j] - r[j + 1], and it is placed at that time:

x_back, c_back, n_back, _ = SurpyvalData.from_xrd(
    times, at_risk, deaths
).to_xcnt()
print("x:", x_back)
print("c:", c_back)
print("n:", n_back)

x: [1. 2. 3. 4. 5.]
c: [0 0 1 0 1]
n: [2 1 1 3 1]

If the risk set ever grows from one time to the next, some items entered late (left truncation). xrd has no record of when each item entered, so the conversion cannot be undone, and SurPyval refuses rather than guessing:

try:
    SurpyvalData.from_xrd([1, 2, 3], [4, 6, 3], [1, 2, 3])
except ValueError as err:
    print(err)

The risk set increases between observation times (late entry / left truncation), and the xrd format has no record of when each item entered, so this data cannot be read from it: give it as SurpyvalData(x, c, n, tl=...) instead.
