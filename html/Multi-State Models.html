Multi-State Models

Note

Every example on this page is executed when the documentation is built, so the outputs shown are produced by the installed version of surpyval.

What a multi-state model is

Ordinary survival analysis follows each unit from one state (“alive”, “working”) until a single event moves it into another (“dead”, “failed”). Many histories have more than two states. A patient can fall ill, recover, fall ill again and die; a pump can run, run degraded, be repaired and fail; a borrower can pay, fall behind, catch up or default. A multi-state model describes such a history as moves between a fixed set of states. A move straight from one state into another is a transition; a state with no way out (death, scrapped, default) is absorbing.

The questions it answers are the ones people ask about such histories:

  • How likely is a unit to be in each state at a given time? These are the state occupation probabilities. In an illness-death model, they say what share of patients are healthy, ill and dead five years on.

  • Starting from one state at time \(s\), how likely is a unit to be in each state at a later time \(t\)? These are the transition probabilities \(P(s, t)\), a matrix with a row for each starting state. “Given that a pump is degraded today, how likely is it to have failed within a year?” is one of its elements.

  • How do covariates change the hazard of each transition, and so the probabilities?

Competing risks are the simplest multi-state model (one starting state and an absorbing state for each cause), and ordinary survival is simpler still (two states, one transition). With a single transient state SurPyval’s multi-state estimate is exactly the competing-risks cumulative incidence of Competing Risks SurPyval Modelling; with one transition, exactly one minus the Kaplan-Meier estimate.

When to use one

Use a multi-state model when units pass through intermediate states that matter: a disease stage, a degraded mode, a repair, a relapse. Ignoring the intermediate state either loses information (fitting only the time to the final state) or biases the answer (treating the move into the intermediate state as censoring, which it is not).

The estimates on this page assume the process is Markov: where a unit goes next, and how soon, depends on the state it is in and the time (on the model’s clock), not on how long it has been in that state or how it got there. The state occupation probabilities from the starting distribution remain valid estimates without that assumption (Datta and Satten, 2001), but the transition probabilities from a later time \(s\) need it. If the time spent in the current state drives the hazard (a “clock-reset” or semi-Markov process), these estimates do not describe it.

How the data are laid out

Each row is a spell: the time a unit spent in one state. A spell has

  • state: the state the unit was in;

  • tl: when the spell began (the unit’s entry into the state, or into the study);

  • x: when it ended;

  • e: the state the unit moved into at x, or missing (None) where the spell ended because observation stopped (censoring);

  • optionally i, the unit (i_col for a DataFrame), and n, a count of identical units.

A unit’s spells follow one another: the second starts where the first ended. A unit can also enter part-way through, in any state (delayed entry, or left truncation): it counts as at risk only from its tl.

This “long” form is the one R’s survival package uses for multi-state data. R’s mstate uses a “stacked” form instead, with one row for every transition a spell could have ended in; surpyval.multistate.to_stacked and from_stacked convert between the two.

From a SurpyvalData

The spells can also be held in a SurpyvalData, the package’s one container for data: s is the state during each row (the spell), e the state moved into at x (blank where the unit was still in s when last seen), i the unit and tl the entry. Every multi-state model fits it directly, fit(data, transitions=...), with the same result as from the arrays; the other data arguments are then left out, and the regressions take the data’s covariates Z with their names. Five patients in an illness-death model:

import surpyval as sp
from surpyval.multistate import MultiState, TransitionMatrix

data = sp.SurpyvalData(
    x=[2, 6, 3, 8, 4, 7, 9],
    s=["healthy", "ill", "healthy", "ill", "healthy", "healthy",
       "healthy"],
    e=["ill", "dead", "ill", None, "dead", None, None],
    i=[1, 1, 2, 2, 3, 4, 5],
    tl=[0, 2, 0, 3, 0, 0, 0],
    unit="months",
)
model = MultiState.fit(data, transitions=TransitionMatrix.illness_death())
model.occupancy(5, "ill")

np.float64(0.4)

Two in five patients are ill at 5 months. SurpyvalData.from_dataframe builds the same data from a table (s_col, e_col, i_col, tl_col).

Data without s is the case of one starting state: every row starts from it, so competing-risks data (the cause in e) fits as it is. The starting state is the one state of transitions that nothing moves into, or "event-free" (the name TransitionMatrix.competing_risks gives it) where no transitions are given; where the transitions have several such states, give s. A row that failed with no state entered (a masked cause), data with no e, and data without s whose units have several rows (stretches of a unit’s life, or repeated events) are refused, saying what fits them.

The terminal flag a of a SurpyvalData is not needed here: a terminal event is the same idea as entering an absorbing state, which the transitions already say, so the fits ignore it.

These models take neither interval- nor left-censored rows (c of 2 or -1: a change of state seen only between two inspections), weights, right truncation, time-varying covariates nor measurements (m); data holding any of them is refused, saying what to do. s is also another name for state in fit, and s_col for state_col in fit_from_df. The panel models below take arrays of visits, not a SurpyvalData: their s is the state seen at a visit, not the state during a row, so fit(data) is refused, saying so.

How the estimate works, in words

At each time a transition is seen, the Aalen-Johansen estimate counts how many units were in each state just before, and how many of them made each move. The share of the units in state \(g\) that moved to \(h\), \(d_{gh} / r_g\), is the estimated chance of that move at that time. Chaining these chances from \(s\) to \(t\) (multiplying the matrices of them) gives the transition probabilities:

\[P(s, t) = \prod_{s < t_j \le t} \left(I + dA(t_j)\right),\]

where \(dA(t_j)\) holds the shares \(d_{gh} / r_g\) off the diagonal and minus their row sums on it. Censored units simply stop counting in \(r\) after they leave, as in the Kaplan-Meier estimate.

The uncertainty comes in three versions, all standard: the Greenwood-type and Aalen-type variances R’s mstate computes, which build up the variance of \(P\) step by step from the variance of each step’s shares, and the infinitesimal jackknife (R survival’s survfit), which adds up how much each unit moves the estimate. They agree closely on data of a reasonable size.

A worked example: progression of MGUS

The MGUS data (Kyle et al., 2002; R’s survival::mgus2) follow 1,384 patients with monoclonal gammopathy of undetermined significance, a condition that can progress to a plasma-cell malignancy (PCM). Patients die with or without progressing: an illness-death model with the states mgus, pcm and death. Times are in months.

Covariates: a Cox model for each transition

MultiStateProportionalHazards fits a proportional-hazards model to each transition: each transition has its own baseline hazard and, by default, its own coefficients. It is fitted as one Cox model, stratified by transition, to the stacked data, which is how R’s mstate does it. Here, the effect of sex and of age (in decades from 70) on each transition:

spells["age70"] = (spells["age"] - 70) / 10
cox = MultiStateProportionalHazards.fit_from_df(
    spells, "x", ["age70", "male"], "e", "state", tl_col="tl",
    i_col="id", transitions=tm,
)

Where few units are left at risk the predicted hazards of leaving a state can add up to more than 1 at one time, and the predicted probabilities can then leave [0, 1]; the model warns when a prediction reaches such a time.

Effects shared by some transitions, and proportional baselines

An effect can also be shared by some transitions only. Here sex is thought to act the same way on the two ways of dying (with or without PCM), but not necessarily on progression: shared takes a dictionary from the covariate to the transitions that share its coefficient, each a (from, to) pair (or its name, "mgus -> death"). The other transitions keep their own coefficient.

into_death = [("mgus", "death"), ("pcm", "death")]
grouped = MultiStateProportionalHazards.fit_from_df(
    spells, "x", ["age70", "male"], "e", "state", tl_col="tl",
    i_col="id", transitions=tm, shared={"male": into_death},
)

This is R mstate’s general design (Putter, Fiocco and Geskus, 2007): one Cox model of the stacked data with a stratum for each transition, or for each group with proportional baselines (with the indicator of each transition but the first as a covariate), and each covariate expanded into a column for each transition or group of transitions. The predictions and their standard errors account for the covariance of the shared coefficients across the transitions, as msfit and probtrans do. One difference from mstate: two transitions that share a baseline have the covariance \(\phi_h \phi_g \, \widehat{\mathrm{var}}\, d\hat{\Lambda}_0\) of their predicted increments (\(\phi\) each one’s relative risk), whereas msfit uses \(\phi_h^2\) (h the lower-numbered transition), which depends on the order the transitions are listed in. The estimates are the same; the standard errors of the predictions differ (by about 7% to 13% in the checks below).

Parametric models: a distribution for each transition

The Aalen-Johansen estimate and the Cox models make no assumption about the shape of each transition’s hazard over time, and so they stop at the last observed time and move in steps. A parametric multi-state model instead gives each transition a distribution (a Weibull, say) on the time since the start, fitted to the spells that could have ended in it. Choose it when you need to

  • extrapolate: predict past the last observation (the share of patients dead at 50 years, the share of pumps failed over a design life longer than the trial), as far as the distributions can be trusted there;

  • draw smooth curves, which do not jump at each observed event, or summarise each transition in a few numbers (a shape and a scale);

  • work with few events, where a step estimate is ragged.

The price is the assumption: each transition’s hazard must follow its distribution. Compare the fit with the Aalen-Johansen estimate where the data are, as below, and with other distributions (dist takes one for every transition or a dictionary with one for each).

Each transition is fitted on its own: its events are the spells that ended in it; the spells in the same state that ended in another transition, or were censored, are censored; and a spell that began at tl (an entry into the state, or a late entry into the study) is left truncated there. That is the maximum-likelihood fit of the whole model, because its likelihood is a product of one factor per transition.

The probabilities then come from the Kolmogorov forward equations, which say how \(P(s, t)\) changes as \(t\) moves on: \(\partial P(s, t) / \partial t = P(s, t)\,Q(t)\), where \(Q(t)\) holds the transition hazards. SurPyval solves them by chaining many short steps, each the exact answer for hazards that are nearly constant over it (the matrix exponential, with a fourth-order correction for hazards that change), on a grid that is refined until each row of \(P(s, t)\) is accurate to about \(10^{-8}\). With exponential transitions (constant hazards) the answer is the matrix exponential \(\exp\{Q\,(t - s)\}\) exactly.

Semi-Markov models: the clock restarts in each state

The models above run every hazard on the time since the start (the clock goes forward: a Markov model). Often the time that matters is the time spent in the current state instead: the time since a repair, since a relapse, since a machine was moved to standby. With clock="reset" each transition’s hazard is a function of the time since the unit entered its ‘from’ state (a semi-Markov model). Each transition is then fitted on the times spent in the state, x - tl, with no truncation; tl must therefore be the time the unit entered the state.

Where a unit is at time \(t\) now depends on when it made each earlier move, so the probabilities are no longer the solution of the forward equations. SurPyval solves the renewal equations instead: the rate at which units enter a state is the sum, over the states they come from, of the rate they entered those states times the chance of leaving for this one after the time since. It counts the entries into each state on a fine grid (evenly spread within each cell), by convolution, and halves the grid until the probabilities settle (to about \(10^{-6}\)). It is exact in the limit, deterministic, and works with recovery (a cycle in the transitions) as well as without; R’s flexsurv answers the same question by simulating paths.

States seen only at visits (panel data)

Often nobody sees a unit change state. A patient’s condition is graded at clinic visits, a component is found worn at an inspection, a survey asks each wave who is employed. All that is known is the state at each visit, so a move happened at some unknown time between two visits, and a unit may even pass through a state between visits that is never seen (ill and recovered again). Spells cannot be written down, and the models above do not apply.

PanelMultiState fits the standard model for such panel data (Kalbfleisch and Lawless 1985, and R’s msm): a Markov chain in continuous time with a constant transition intensity for each allowed move, the rate of that move while a unit is in its ‘from’ state. Over a gap of length \(t\) the probability of going from state \(r\) to state \(s\), by any route, is element \((r, s)\) of the matrix exponential \(P(t) = \exp(Q t)\), \(Q\) the matrix of intensities. Each unit contributes the probability of the states it was seen in, given its first, multiplied over the gaps between its visits; the intensities that make the data most likely are the estimates. The mean stay in a state is one over the total rate of leaving it.

The data are one row per visit: the time (x), the state seen (s) and the unit (i). Three kinds of row go beyond a plain visit:

  • a move into an absorbing state timed exactly (a death, a scrapping): name the state in exact_entry, and the row means “in some other state just before, entered this one at this time”;

  • a visit that saw only a set of states (“alive, condition not recorded”): give it a code and say what the code means in censored, {"alive": ["healthy", "ill"]};

  • a move seen as it happened, the unit having stayed in its previous state until then: obstype="exact" on that row.

Unlike the spell models, the allowed transitions must be given: they cannot be read off the visits.

import numpy as np
from scipy.linalg import expm

PanelMultiStateRegression puts covariates on the log intensities, each transition with its own coefficients or one shared by every transition; a row’s covariates hold over the gap that starts at it, so they may change from visit to visit. The coefficients are log intensity ratios, and summary shows the ratios with their bounds. pci (a list of times) lets every intensity change at those times, each later period multiplying each transition’s intensity by its own factor.

The model assumes the future depends only on the current state (Markov) and, apart from pci and covariates, that the intensities stay the same over time. The standard errors come from the observed information (the exact gradient of the likelihood, differenced once), and the bounds on probabilities from the delta method through the exact derivatives of the matrix exponential. Misclassified states (a hidden Markov model, where a visit can record the wrong state) are not built.

How it was checked

The estimates and every variance agree with R to rounding: the occupation probabilities and their jackknife standard errors with survival’s survfit (from the start, and from a later time, with delayed entry and tied times); the transition probabilities and their Greenwood-type and Aalen-type standard errors with mstate’s probtrans; and the Cox models’ coefficients and predictions, with their standard errors, with mstate’s msfit and probtrans (Breslow’s and Efron’s ties, transition-specific effects, effects shared by every transition or by some, and proportional baselines; for the last, with msfit’s covariance of two transitions sharing a baseline, as above, and its log partial likelihood). The same was checked, outside the test suite, on mstate’s own ebmt3 data (an illness-death model of transplant patients, with transition-specific, partly shared and proportional-baseline models): the coefficients and log partial likelihood agree to about \(10^{-10}\), the probabilities to \(10^{-12}\), and the standard errors to \(10^{-11}\) (with msfit’s covariance term; 7% with the one above). With one transient state the estimate is SurPyval’s competing-risks cumulative incidence, and with one transition its Kaplan-Meier estimate with Greenwood’s variance. Simulated Markov models are recovered within their bounds. The script that produced R’s numbers is scripts/reference/reference_r_multistate.R.

The parametric models were checked against R’s flexsurv (fitting each transition with flexsurvreg and solving the forward equations with pmatrix.fs), on the same data: the fits reach the same maximum, and with flexsurv’s parameters the transition probabilities agree to about \(10^{-11}\). The forward equations were also checked against a closed form (Weibull hazards of different shapes, one infinite at 0), and with one transient state the occupation probabilities equal ParametricCompetingRisks’ cumulative incidences. The delta-method standard errors match the spread of the probabilities over simulated parameters, and simulated Markov models are recovered within their bounds. The script is scripts/reference/reference_r_multistate_parametric.R.

The semi-Markov models were checked against a closed form (an illness-death model with Weibull hazards of the time in each state, one infinite at 0, where the probabilities and lengths of stay are one-dimensional integrals) to \(10^{-6}\); with exponential hazards (where the clock does not matter) against the forward equations, with recovery; against a seeded simulation of paths with recovery; and against R’s flexsurv: the clock-reset fits reach flexsurv’s maximum, and with flexsurv’s parameters the probabilities agree with its simulation (pmatrix.simfs, a million paths) within its Monte Carlo error, as do the lengths of stay (totlos.simfs). The clock-forward lengths of stay agree with totlos.fs to about \(10^{-8}\) of the time. The delta-method standard errors match the spread over simulated parameters, and a calibration study checks the coverage of the bounds. The script is scripts/reference/reference_r_multistate_semimarkov.R.

The panel-data models were checked against R’s msm 1.9 on a simulated four-state model with exactly timed deaths and visits that saw only “alive”: the log-likelihoods agree to \(10^{-12}\) and the intensities, standard errors, bounds, transition probabilities, mean stays and intensity ratios (with covariates that change between visits, an effect shared by every transition, and piecewise-constant intensities) to about \(10^{-6}\). With every move seen when it happens the estimates are the numbers of moves over the time at risk, and with two states the fit is the exponential fit to interval-censored lifetimes. Simulated panel data show the bounds on the intensities, the occupation probabilities and the mean stays covering at their nominal level. The script is scripts/reference/reference_r_multistate_panel.R.

What is not here yet

The spell models refuse interval-censored changes of state: for states seen only at visits use PanelMultiState, which has no hidden Markov (misclassification) model yet. The parametric models have no likelihood-ratio or bootstrap bounds. The clock reset is offered for the parametric spell models only: a Cox model per transition on the time in the state would need its probabilities simulated over step hazards, and the Aalen-Johansen estimate is Markov by construction (for a non-Markov process its occupation probabilities are still consistent, Datta and Satten, 2001, but its transition probabilities from a later time are not). Covariates that change over a stay are not taken.

The states of a multi-state model and the transitions allowed between them.

A multi-state model follows each unit through a set of states (for example “healthy”, “ill” and “dead”). class surpyval.multistate.MultiState

Bases: SerialisableMixin

Non-parametric multi-state model: the Aalen-Johansen estimate of the probabilities of moving between states.

Each unit moves through a set of states (see TransitionMatrix), and the data are its spells: the time it spent in one state, from its entry tl to its exit x, and the state it moved into at x (or none, if it was last seen then). From the numbers at risk in each state and the transitions seen at each time, the Nelson-Aalen increments \(dA_{gh}(t_j) = d_{gh}(t_j) / r_g(t_j)\) give the transition probability matrix by the product integral

\[P(s, t) = \prod_{s < t_j \le t} \left(I + dA(t_j)\right),\]

whose element \((a, b)\) is the probability of being in state \(b\) at \(t\) for a unit in state \(a\) at \(s\) (Aalen and Johansen, 1978). It assumes the process is Markov: where a unit goes next depends on its state and the time, not on how it got there. The state occupation probabilities occupancy are a row of it, or the rows averaged over the states the units were in at \(s\); they still estimate the population’s occupation probabilities when the process is not Markov (Datta and Satten, 2001).

With one transient state and absorbing states for the causes, this is the competing-risks cumulative incidence of CompetingRisks; with one transition, one minus the Kaplan-Meier estimate.

A spell is at risk in its state at \(t\) when \(tl < t \le x\), so a unit observed from part-way through its history (delayed entry, left truncation) counts only from its entry.

Call the class method MultiState.fit (or fit_from_df); it returns a fitted instance.

class surpyval.multistate.MultiStateProportionalHazards

Bases: SerialisableMixin

Multi-state proportional-hazards regression: a Cox model for each transition, and the transition and state occupation probabilities predicted from them for a unit with given covariates.

The hazard of the transition \(h\) (from state \(g\) to state \(k\)) of a unit with covariates \(z\) is

\[\lambda_h(t \mid z) = \lambda_{h,0}(t) \exp(\beta_h^\top z),\]

each transition with its own baseline hazard and, by default, its own coefficients \(\beta_h\). A covariate named in shared has one coefficient for every transition instead, or one for each group of transitions given for it (the others keep their own). Transitions named together in proportional_baselines share one baseline hazard up to a constant factor, \(\lambda_{h,0}(t) = \lambda_{r,0}(t) e^{\gamma_h}\), with \(r\) the group’s first transition. The model is fitted as one Cox model to the stacked data (one row for each transition a spell could have ended in; see to_stacked()), stratified by transition, with each covariate expanded into one column per transition (Andersen and Keiding, 2002; Putter, Fiocco and Geskus, 2007), which is R mstate’s approach. With every effect transition-specific the coefficients are those of a separate Cox model of each transition.

The prediction for a covariate row \(z\) is the Aalen-Johansen product integral of the predicted cumulative hazards, \(dA_h(t \mid z) = d\hat{\Lambda}_{h,0}(t) \exp(\hat{\beta}_h^\top z)\), and its standard errors are those of mstate’s msfit and probtrans: they include the uncertainty of the coefficients. Like the non-parametric MultiState it assumes the process is Markov.

Call the class method MultiStateProportionalHazards.fit (or fit_from_df); it returns a fitted instance.

class surpyval.multistate.ParametricMultiState

Bases: _ParametricMultiStateBase

A parametric multi-state model: a parametric distribution for the hazard of each transition, and the transition and state occupation probabilities they imply.

The hazard of the transition from state \(g\) to state \(k\) is that of a distribution (Weibull by default) on the time since the start (by default the clock goes forward: a Markov model). Each transition’s distribution is fitted to the spells in its ‘from’ state, where the spells that ended in another transition, or were censored, are censored, and a spell that began at tl is left truncated there (delayed entry). That is the maximum-likelihood fit of the whole model, since its likelihood is a product of one factor per transition.

With clock="reset" each hazard is instead a function of the time spent in the current state (a semi-Markov model): each transition is fitted on the durations x - tl, and the probabilities come from the renewal equations, solved by convolution on a grid refined until they are accurate to about \(10^{-6}\); the forward equations below are those of the default clock="forward".

The transition probabilities \(P(s, t)\) solve the Kolmogorov forward equations \(\partial P(s, t) / \partial t = P(s, t) Q(t)\), \(Q(t)\) the matrix of the transition hazards, which are solved by product integration on an adaptive grid to an accuracy of about \(10^{-8}\) in each row (the sum of the absolute errors of its elements) over the span of the data, and in proportion beyond it. The bounds on the state occupation probabilities come from the delta method over every transition’s parameters.

Unlike the non-parametric MultiState, its curves are smooth and can be extended past the data, as far as the distributions can be trusted there.

Call the class method ParametricMultiState.fit (or fit_from_df); it returns a fitted instance.

Andersen, P. K. and Keiding, N. (2002), “Multi-state models for event history analysis”, Statistical Methods in Medical Research, 11(2), 91-115.

Jackson, C. H. (2016), “flexsurv: a platform for parametric survival modeling in R”, Journal of Statistical Software, 70(8), 1-33.

class surpyval.multistate.PanelMultiState

Bases: _PanelMultiStateBase

A multi-state Markov model for panel data: units whose state is seen only at visits (inspections, clinic visits, survey waves).

Each allowed move from state \(r\) to state \(s\) has a constant transition intensity \(q_{rs}\): the rate of that move while a unit is in \(r\). The chance of being in \(s\) a time \(t\) after being in \(r\) is element \((r, s)\) of \(P(t) = \exp(Q t)\), \(Q\) the matrix of intensities, so a unit may make several moves between two visits, unseen. The intensities are fitted by maximum likelihood from the states seen at each visit (Kalbfleisch and Lawless 1985), as R’s msm does: each unit contributes the probability of its sequence of states given its first, a product of elements of \(P\) over the gaps between its visits.

The mean stay in a state is \(-1 / q_{rr}\), and the probabilities of being in each state later follow from \(P(t)\); their bounds come from the delta method over the intensities.

Call the class method PanelMultiState.fit (or fit_from_df); it returns a fitted instance. For covariates on the intensities use PanelMultiStateRegression.

References

Kalbfleisch, J. D. and Lawless, J. F. (1985), “The analysis of panel data under a Markov assumption”, Journal of the American Statistical Association, 80(392), 863-871.

Jackson, C. H. (2011), “Multi-state models for panel data: the msm package for R”, Journal of Statistical Software, 38(8), 1-29.

property parameter_bounds: list[tuple[float | None, float | None]]

one (low, high) pair per entry of the vector with_params() takes, in the order of covariance_names (None for an end with no bound).

A parameter set drawn inside these ranges is one with_params does not refuse for being out of range, and one just outside a finite end is refused. Draw a parameter bounded on one side on the log scale of its distance from that end, and one bounded on both on the logit scale between them. Whether an end itself is allowed depends on the parameter (a probability may be 0 where a scale may not), so keep draws strictly inside.

A few models also constrain their parameters jointly, which no per-parameter range can say, and with_params refuses a set that breaks the joint constraint, saying so: a mixture’s weights sum to 1; a Uniform’s a is below its b (as a Beta4’s are); a Royston-Parmar spline does not fall; a Binomial’s n is a whole number. The entry of a parameter with_params ignores (held fixed in the fit, or an accelerated life model’s life parameter) gives the parameter’s range all the same. An accelerated life model’s life-model parameters can have ranges that depend on the stresses fitted to; a model loaded from a dict saved without its data gives them as unbounded.

class surpyval.multistate.PanelMultiStateRegression

Bases: _PanelMultiStateBase

A multi-state Markov model for panel data with covariates on the transition intensities: \(q_{rs}(z) = q_{rs} \exp(\beta_{rs}^T z)\), each transition with its own coefficients, or one coefficient for every transition for the covariates named in shared.

Covariates may change from visit to visit: those of a row hold over the gap that starts at it (as in R msm). Otherwise the model is PanelMultiState; its predictions are for given covariates.

Call the class method PanelMultiStateRegression.fit (or fit_from_df); it returns a fitted instance.

References

Marshall, G. and Jones, R. H. (1995), “Multi-state models and diabetic retinopathy”, Statistics in Medicine, 14(18), 1975-1983.

Jackson, C. H. (2011), “Multi-state models for panel data: the msm package for R”, Journal of Statistical Software, 38(8), 1-29.

property parameter_bounds: list[tuple[float | None, float | None]]

one (low, high) pair per entry of the vector with_params() takes, in the order of covariance_names (None for an end with no bound).

A parameter set drawn inside these ranges is one with_params does not refuse for being out of range, and one just outside a finite end is refused. Draw a parameter bounded on one side on the log scale of its distance from that end, and one bounded on both on the logit scale between them. Whether an end itself is allowed depends on the parameter (a probability may be 0 where a scale may not), so keep draws strictly inside.

A few models also constrain their parameters jointly, which no per-parameter range can say, and with_params refuses a set that breaks the joint constraint, saying so: a mixture’s weights sum to 1; a Uniform’s a is below its b (as a Beta4’s are); a Royston-Parmar spline does not fall; a Binomial’s n is a whole number. The entry of a parameter with_params ignores (held fixed in the fit, or an accelerated life model’s life parameter) gives the parameter’s range all the same. An accelerated life model’s life-model parameters can have ranges that depend on the stresses fitted to; a model loaded from a dict saved without its data gives them as unbounded.
