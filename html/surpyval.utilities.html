Utilities

The data containers the fitters build from your arrays, the functions that convert between SurPyval’s data formats, and the abstract base classes every model derives from. The formats themselves – xcnt (times, censoring flags, counts, truncation), xrd (times, numbers at risk, deaths) and fsli (lists of failures, suspensions, left- and interval-censored values) – are defined in Conventions, and Data Wrangling Examples shows them in use.

Data Classes

SurpyvalData holds univariate xcnt data, split by censoring type; every univariate fitter builds one, and the parametric, non-parametric and regression fit methods accept one in place of the arrays (Weibull.fit(data)). Its constructors from_observations and from_xrd read the fsli and xrd layouts, and to_xcnt, to_observations and to_xrd write them. EventHistoryData holds recurrent-event data (each row an event of an item); build it from one ItemHistory per item (EventHistoryData.from_items), from dictionaries keyed by item (from_histories), or from arrays with handle_xicn.

Lifetime data: one row per item (or per group of identical items, counted n), each observed exactly, right censored, left censored or interval censored, within its truncation window, with the item’s id, event type and covariates where they are given. The parametric, non-parametric and regression fit methods take one in place of the arrays: Weibull.fit(data), CoxPH.fit(data), CompetingRisks.fit(data).

Build one from each item’s record, from_items() (ItemLifetime), from the times of each kind, from_observations(), from a DataFrame, from_dataframe(), from the xrd layout, from_xrd(), or from the xcnt arrays (Conventions) with the constructor, which checks them as every fitter does. The data is read back as records (item(), to_items(), records()), tables (to_dataframe(), to_observations(), to_xcnt()) or JSON (to_json()), described by summary(), and reshaped for another analysis (without(), for_event_type(), select(), censor_at(), …). len(data) is its rows; n_items its items.

Its arrays are x (a [lower, upper] row where any observation is an interval), c, n and t (tl and tr, its columns), Z (the covariates, named by covariate_names), e (the event types), ids (each row’s unit, also called i), for multi-state data s (the state each row’s unit was in), and a (1 where a row’s event ended its unit’s history for good). For the likelihoods it also holds the rows split by kind of observation (x_o, n_o; x_r, n_r; x_l, n_l; x_il, x_ir, n_i; and Z_o, … with covariates): a censored row with a finite truncation bound on its censored side is stored as an interval ending at that bound, so the likelihood uses the probability of the part of the window it could have fallen in. These are left out of dir(data).

Initialize a SurpyvalData instance for survival analysis.

Validates, sorts, and stores survival data in the xcnt format. Supports uncensored, right/left/interval-censored, and truncated observations. Can convert to xrd format and select subsets by censoring type.

Parameters:

  • x (array-like, optional) – The primary data array of failure/event times. When c is 2 the corresponding x entry is a 2-element array [left, right].

  • c (array-like, optional) – Censoring flags for each value in x: * 0 = uncensored (the event, a failure or a death, was at x) * 1 = right censored * -1 = left censored * 2 = interval censored

  • n (array-like, optional) – Number of occurrences for each value in x (positive whole numbers).

  • t (array-like, optional) – 2D array of truncation bounds [left, right] for each value in x.

  • xl (array-like, optional) – Left interval bounds for interval censored data, paired with ‘xr’. Given with ‘x’, each row is read on its own: an exact time in ‘x’ (with ‘xl’ and ‘xr’ blank: None, NaN or pandas’ NA), or a range in ‘xl’ and ‘xr’ (with ‘x’ blank), read by its bounds as a [xl, xr] row is ([v, inf] right censored, [-inf, v] left censored, [v1, v2] interval censored, [v, v] exact). A row giving both is left out with a warning, and so are its entries in every other per-row argument; a row giving neither is refused. A c given must agree with each range (a blank c on a range row is read from the range).

  • xr (array-like, optional) – Right interval bounds for interval censored data, paired with ‘xl’; with ‘x’, as for ‘xl’.

  • tl (array-like or scalar, optional) – Left truncation bounds. Cannot be used with ‘t’. May be given alone (the right bound is then infinite) or with ‘tr’.

  • tr (array-like or scalar, optional) – Right truncation bounds. Cannot be used with ‘t’. May be given alone (the left bound is then minus infinity) or with ‘tl’.

  • Z (array-like, optional) – Covariates, one row per value of x (see also add_covariates()). Giving Z turns group_and_sort off, so the rows stay aligned with x. A DataFrame’s columns name the covariates.

  • covariate_names (list of str, optional) – The name of each column of Z; fit(data) names the model’s coefficients by them, and with_covariates picks columns by them.

  • e (array-like, optional) – The event type (failure mode or cause) of each row, for the competing-risks fitters, which take it from the data; a suspension (c == 1) has none (None). Giving e turns group_and_sort off, as Z does. With states s, e is the state the unit moved into at x (a failure mode is a state entered from the one starting state), blank (None, NaN or “”) where it was still in s.

  • ids (array-like, optional) – Each row’s item (unit) id (text or numbers, each once), as from_items gives them: data.item(id) and select(ids=...) then find the rows. Giving ids turns group_and_sort off, as Z does. i is the same argument; give one or the other. With states s a unit has a row for each stay in a state, so an id may repeat.

  • unit (str, optional) – The unit of the times ("hours", "km"), a label kept with the data as a model keeps its unit; fit(data) gives it to the model.

  • w (array-like or scalar, optional) – Sampling, propensity or censoring weights: how many units of the population each unit of a row stands for (any positive finite number), beside its count n of identical units. A fit of weighted data gives the weighted estimate with a robust (sandwich) variance, and refuses the bounds weights make invalid (see Weighted Data). Rows are grouped only where their weights are equal too. Without w the data is unweighted (data.w is None).

  • s (array-like, optional) – The state each row’s unit was in during the row (from its entry, tl, to x), for multi-state data: one state per row, text or numbers, kept as given. Without s every row starts from the one initial state, as ordinary survival and competing-risks data do. With s, c is read from e where c is left out (blank e: 1, still in s; otherwise 0, moved into e at x), and a c given must agree with e (a row with c == 1 has a blank e, any other row a state in e). Giving s turns group_and_sort off, as Z does. Fits that are not multi-state refuse data with more than one state in s.

  • i (array-like, optional) – Each row’s unit (item) id; the same argument as ids (data.i and data.ids are the same list). A unit may have several rows, in time order: stretches of its own clock, (tl, x], each with its covariates fixed (still running at x, c == 1, then the next row from x), or repeated events (a == 0), ending with a terminal event (a == 1) or still running (c == 1). A row that starts before the previous row of its unit ends is refused.

  • a (array-like, optional) – Each row’s terminal flag: 1 where the row’s event ended the unit’s history for good (scrapped, written off, died: an absorbing state, as in multi-state data), 0 where the unit carried on (a repair, a recurrent event) or the row has no event (c == 1, where 1 is refused). A blank (None, NaN) on an event row is read as 1 on the unit’s last row and 0 on an earlier one; data.a_inferred marks those rows. A row after one with a == 1 of the same unit is refused. Without a, data.a is None unless a unit has several rows (then it is inferred), and with states s it is kept and checked only (the transitions say which states are absorbing).

  • m (Measurements or dict, optional) – Readings taken on the units over their lives, on their own timeline (Measurements, or a dict it is built from: {i: {x: value}} or {name: {i: {x: value}}}), linked to the rows by i, which it needs; data.m (data.markers is the same store). A unit with readings but no rows is warned of and kept.

  • group_and_sort (bool, default=True) – Whether to group and sort the data. Set False when using covariates to maintain data order.

  • handle (bool, default=True) – Whether to validate and process the input data. Set False for pre-validated data: x, c, n and a two-column t exactly as xcnt_handler() returns them.

Examples

Basic usage with uncensored data: >>> import numpy as np >>> from surpyval import SurpyvalData >>> x = np.array([1, 2, 3]) >>> data = SurpyvalData(x)

Right censored data: >>> x = np.array([1, 2, 3]) >>> c = np.array([0, 1, 1]) # 2 and 3 are censored >>> data = SurpyvalData(x, c)

Interval censored data: >>> xl = np.array([1, 2, 3]) >>> xr = np.array([2, 3, 4]) >>> data = SurpyvalData(xl=xl, xr=xr)

Interval Censored with nested 2 arrays: >>> x = [1, 2, [2, 5], 3, 6] >>> c = [0, 1, 2, 0, 0] >>> data = SurpyvalData(x=x, c=c)

With truncation: >>> x = np.array([1, 2, 3]) >>> t = np.array([[0, 5], [0, 5], [0, 5]]) >>> data = SurpyvalData(x, t=t)

censor_at(age: Any) → Any

The data as seen if observation stopped at age (administrative censoring, as at the end of a study or a warranty): what happened after age is no longer seen. A failure found between inspections either side of age becomes right censored at the last good inspection, since it may have come after age; an item that came under observation at or after age is left out. A lifetime keeps the marker readings taken up to its new end.

age is one age for every item, in the data’s time unit; {id: age}, a cut-off per item (the items it leaves out are kept as they are); or a function of each item’s record giving its cut-off: a study that ends on one date ends at a different age for each item, data.censor_at(lambda item: (end - item.attribute("installed")).days).

A history’s failures counted between two inspections, or a change of state between two, are known only as a whole: where age falls between those inspections, the history is cut at the earlier one (and left out where that is before its first look).

classmethod concat(datasets: Any) → SurpyvalData

The rows of several datasets as one: SurpyvalData.concat([a, b, c]), also a + b (and sum([a, b, c])). Each dataset keeps what it has: its counts, weights w, event types e, states, terminal flags a, truncation, attributes, time-varying covariates and measurements m. The rows are then grouped and sorted as the constructor does (kept in order where the data has ids, event types, covariates, states or attributes).

Refused, saying what to do: datasets in different units (or one with a unit and one without), with different covariates (by name and order), some with item ids and some without (and likewise states and time-varying covariates), failures without event types beside data with them, and an item id in more than one dataset (an id is one item, so their rows would become one history: rename the ids first). Weighted and unweighted datasets combine, the unweighted rows at weight 1.

Parameters:

datasets (list of SurpyvalData) – The datasets, at least one.

Return type:

SurpyvalData

enter_at(age: Any) → Any

The data as if observed only from age (left truncation): only items known to have reached age without failing – for a history, in a known state – stay in, with age as the start of their observation; a failure found between inspections either side of age, or known only to have happened before a look, may have come before it, so its item is left out. age is one age for every item, {id: age}, an entry per item (the items it leaves out are kept as they are), or a function of each item’s record giving its entry. A lifetime keeps the marker readings taken from age on.

A history goes on after its failures, so where age falls between two inspections that count failures, or a change of state, or before a first look, its observation starts instead at the later inspection, from which it is known again.

for_event_type(event_type: Any, masked: str = 'censor') → Any

The data of one failure mode, event_type (or of several taken as one, given as a list or set), as for a cause-specific analysis: for a lifetime, a failure of another mode becomes right censored at its age (at the last good inspection, for one found between inspections; one known only to have happened before an age is left out); for a history, the other modes’ failures are removed and its observation runs at least to the last of them. The result has no event types.

Lifetimes lose their right truncation, with a warning: an item is in right-truncated data because its first failure, of any mode, came by the truncation age, and a fit of one mode cannot account for a selection that depends on every mode, so the result is treated as not right truncated (an approximation). Kept, the truncation would turn each other mode’s failure into a failure of this one before the truncation age. Left truncation is kept.

Failures whose type was not recorded (masked causes) may or may not be of this type; masked says how they are taken: "censor" (the default) as not of it, with a warning that its rate is underestimated if some were; "count" as of it (then overestimated if some were not); "refuse" refuses the data.

Validate data in one format and convert it to another. The methods of SurpyvalData above are the way to do this; these functions are what they use. surpyval.utils.xcnt_handler(x: ArrayLike | None = None, c: ArrayLike | None = None, n: ArrayLike | None = None, t: ArrayLike | None = None, xl: ArrayLike | None = None, xr: ArrayLike | None = None, tl: ArrayLike | Number | None = None, tr: ArrayLike | Number | None = None, group_and_sort: bool = True) → tuple[NDArray, NDArray, NDArray, NDArray]

Main handler that ensures any input to a surpyval fitter meets the requirements to be used in one of the parametric or nonparametric fitters.

Deprecated since version 0.25: surpyval.xcnt_handler is deprecated (2026-10-12), and is removed in the first release on or after 2027-04-12. Use::

SurpyvalData(x, c, n, t, …).to_xcnt()

It converts the inputs to numpy arrays and checks them: x is not empty and has no NaN (a scalar is one observation); c holds only -1, 0 and 1 (and 2 for a two-column x); n holds positive whole numbers; the truncation bounds have no NaN and the window of each row has its left bound below its right bound. For two-column x, a row with equal values is not an interval, a row with different values must be flagged 2 (when c is given), and an infinite end turns the row into one-sided censoring: [v, inf] becomes right censored at v and [-inf, v] left censored at v. If no interval is left, x is returned with one column.

Each row must then fit its truncation window (tl, tr]: a single value lies strictly above tl and at or below tr – strictly below tr if it is right censored – whether x has one column or two; an interval [xl, xr] needs tl <= xl and xr <= tr. Identical rows are then merged (their counts summed) and the rows sorted with xcnt_sort().

Parameters:

  • x (array) – array of values of variable for which observations were made.

  • c (array, optional (default: None)) – array of censoring values (-1, 0, 1, 2) corresponding to x

Abstract Base Classes

Every model derives from one of these, exported from surpyval; they define the minimal interface a model provides and are useful for isinstance checks and for writing new model types.

class surpyval.distribution.Distribution

Bases: ABC

Root abstract base class that every surpyval model inherits from.

The contract shared by all models – parametric, nonparametric, mixtures, compositions and degenerate models – is the survival interface:

  • sf() the survival (reliability) function

  • ff() the cumulative distribution (failure) function

Hf() is provided as a default derived from sf() and may be overridden by models with a closed form. Statistical summaries such as moment, entropy, random and to_dict are not part of this minimal contract; the ParametricDistribution and NonParametricDistribution subclasses add the ones appropriate to their model family.

Examples

It is abstract; every fitted model is one, whatever its family:

>>> import numpy as np
>>> from surpyval import KaplanMeier, Weibull
>>> from surpyval.distribution import Distribution
>>> x = np.array([1, 2, 3, 4, 5])
>>> models = [Weibull.fit(x), KaplanMeier.fit(x)]
>>> all(isinstance(m, Distribution) for m in models)
True
>>> [m.sf([2.5]).round(4) for m in models]
[array([0.609]), array([0.6])]

class surpyval.distribution.MultivariateDistribution

Bases: ABC

A jointly-specified model of several correlated event-time series.

Unlike Distribution, whose functions take a single random variable, the multivariate interface is evaluated at a point in several dimensions – x is array-like with one column per series. Concrete implementations (e.g. copula models) glue together ordinary univariate surpyval margins with a dependence structure, so the contract is the joint survival interface plus sampling:

  • cdf() the joint cumulative distribution P(X_1<=x_1, ...)

  • sf() the joint survival P(X_1>x_1, ...)

  • pdf() the joint density

  • random() draw correlated samples (one row per realisation)

Examples

It is abstract; a copula model is one:

>>> from surpyval import Weibull
>>> from surpyval.distribution import MultivariateDistribution
>>> from surpyval.multivariate import Clayton
>>> margins = [
...     Weibull.from_params([10, 2]),
...     Weibull.from_params([20, 3]),
... ]
>>> model = Clayton.from_params([2.0], margins)
>>> isinstance(model, MultivariateDistribution)
True
>>> model.sf([[5, 15], [10, 20]]).round(4)
array([0.624 , 0.2354])
