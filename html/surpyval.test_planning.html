Test Planning

Functions that plan reliability tests before they are run: demonstration tests (fixed-length and sequential), life tests sized for the precision of an estimate, accelerated life tests, and the sample size and power of a comparison of two groups, or of a failure rate before and after a change. Import them from surpyval.test_planning. Worked examples are in Test Planning with SurPyval.

Demonstration tests

surpyval.test_planning.demonstration_sample_size(reliability: float, failures: int = 0, *, alpha_ci: float = 0.05, test_multiple: float = 1.0, shape: float | None = None) → int

The fewest units whose test demonstrates a reliability.

The smallest n for which n units tested, with at most failures of them failing, demonstrate reliability over a mission at the confidence level 1 - alpha_ci: the chance that so few fail, were the reliability only the target, is at most alpha_ci. With no failures this is the success run, n = ln(alpha_ci) / ln(reliability) rounded up, the inverse of surpyval.success_run(). Testing each unit for test_multiple missions, with the lifetime’s Weibull shape known, needs fewer units (the extended success run, or Weibayes).

Any argument may be an array: the answer is then an array of the arguments’ broadcast shape, one plan for each element.

Parameters:

  • reliability (float) – The reliability to demonstrate over one mission, in (0, 1).

  • failures (int, optional) – The failures the test allows, by default 0.

  • alpha_ci (float, optional) – Keyword only: the consumer’s risk, the chance that a design no better than the target passes, by default 0.05 (95% confidence).

  • test_multiple (float, optional) – How many missions long each unit’s test is, by default 1.0.

  • shape (float, optional) – The Weibull shape of the lifetime, needed when test_multiple is not 1.

Returns:

The number of units to test.

Return type:

int

Raises:

ValueError – If an argument is out of range, or test_multiple is not 1 and no shape is given.

Examples

59 units with no failures demonstrate 95% reliability at 95% confidence, and allowing one failure takes 93:

>>> from surpyval.test_planning import demonstration_sample_size
>>> demonstration_sample_size(0.95)
59
>>> demonstration_sample_size(0.95, failures=1)
93

Testing each unit for two missions, for a wear-out shape of 2, needs a quarter of the units:

>>> demonstration_sample_size(0.95, test_multiple=2.0, shape=2.0)
15
surpyval.test_planning.demonstrated_reliability(n: int, failures: int = 0, *, alpha_ci: float = 0.05, test_multiple: float = 1.0, shape: float | None = None) → float

The reliability a finished test demonstrated.

The lower one-sided 1 - alpha_ci confidence bound on the reliability over a mission, from n units tested with failures of them failing: the Clopper-Pearson bound, the smallest reliability for which so few failures have a chance of at least alpha_ci. With no failures it is alpha_ci ** (1 / n), surpyval.success_run(). A test of test_multiple missions per unit, with the lifetime’s Weibull shape known, demonstrates that bound to the power 1 / test_multiple ** shape over one mission.

Any argument may be an array: the answer is then an array of the arguments’ broadcast shape.

Parameters:

  • n (int) – The number of units tested, at least 1.

  • failures (int, optional) – How many of them failed, from 0 to n, by default 0.

  • alpha_ci (float, optional) – Keyword only: the significance level of the one-sided bound, by default 0.05 (95% confidence).

  • test_multiple (float, optional) – How many missions long each unit’s test was, by default 1.0.

  • shape (float, optional) – The Weibull shape of the lifetime, needed when test_multiple is not 1.

Returns:

The demonstrated reliability over one mission.

Return type:

float

Raises:

ValueError – If an argument is out of range, or test_multiple is not 1 and no shape is given.

Examples

>>> from surpyval.test_planning import demonstrated_reliability
>>> round(demonstrated_reliability(59), 4)
0.9505
>>> round(demonstrated_reliability(93, failures=1), 5)
0.95001

The shortest test, as a multiple of the mission time, for which n units with at most failures failing demonstrate reliability at the confidence level 1 - alpha_ci, the lifetime’s Weibull shape known (the extended success run, or Weibayes). Below 1, a test shorter than a mission is enough.

  • n (int) – The number of units to test, more than failures.

  • failures (int, optional) – The failures the test allows, by default 0.

  • shape (float) – Keyword only: the Weibull shape of the lifetime.

  • alpha_ci (float, optional) – Keyword only: the consumer’s risk, by default 0.05 (95% confidence).

Returns:

The test length, in missions.

Return type:

float

Raises:

ValueError – If an argument is out of range.

Examples

Twenty units, for a wear-out shape of 2, each run about 1.7 missions to demonstrate 95% reliability at 95% confidence (with a test of one mission, 59 units would be needed):

surpyval.test_planning.demonstration_test_time(reliability: float, n: int, failures: int = 0, *, mission_time: float, shape: float, alpha_ci: float = 0.05) → float

How long each of n units must be tested to demonstrate a reliability over a mission, the lifetime’s Weibull shape known.

The extended success run (Weibayes, Abernethy’s New Weibull Handbook, ch. 6) in the units of mission_time: the test length of demonstration_test_multiple() times the mission. With no failures allowed it is the closed form

\[T = t_m \left(\frac{\ln \alpha}{n \ln R}\right)^{1/\beta},\]

the time by which a Weibull of shape \(\beta\) whose reliability over the mission \(t_m\) is only \(R\) would have let all n units survive with a chance of \(\alpha\). With failures allowed, the binomial (Clopper-Pearson) bound replaces \(\alpha^{1/n}\), as in demonstrated_reliability().

Any argument may be an array: the answer is then an array of the arguments’ broadcast shape.

Parameters:

  • reliability (float) – The reliability to demonstrate over one mission, in (0, 1).

  • n (int) – The number of units to test, more than failures.

  • failures (int, optional) – The failures the test allows, by default 0.

  • mission_time (float) – Keyword only: the length of the mission the reliability is over, positive, in any unit of time.

  • shape (float) – Keyword only: the Weibull shape of the lifetime.

  • alpha_ci (float, optional) – Keyword only: the consumer’s risk, by default 0.05 (95% confidence).

Returns:

How long each unit is tested, in the units of mission_time.

Return type:

float

Raises:

ValueError – If an argument is out of range.

Examples

Ten units, a believed wear-out shape of 2, to demonstrate 90% reliability over 1000 hours at 90% confidence: each runs about 1478 hours with no failure:

>>> from surpyval.test_planning import demonstration_test_time
>>> round(demonstration_test_time(0.9, 10, mission_time=1000.0,
...                               shape=2.0, alpha_ci=0.1))
1478

  • test_multiple (float, optional) – How many missions long each unit’s test is, by default 1.0.

  • shape (float, optional) – The Weibull shape of the lifetime, needed when test_multiple is not 1.

Returns:

The probability of passing.

Return type:

float

Raises:

ValueError – If an argument is out of range, or test_multiple is not 1 and no shape is given.

surpyval.test_planning.mtbf_test_time(mtbf: float, failures: int = 0, *, alpha_ci: float = 0.05, failure_terminated: bool = False) → float

The total test time that demonstrates an MTBF, at a constant failure rate.

The unit time (summed over the units, failed ones repaired or replaced) a time-terminated test needs, with at most failures failures, to demonstrate mtbf at the confidence level 1 - alpha_ci: mtbf * chi2.ppf(1 - alpha_ci, 2 * failures + 2) / 2. A failure-terminated test, which runs until its failures-th failure, demonstrates mtbf if that failure comes after mtbf * chi2.ppf(1 - alpha_ci, 2 * failures) / 2: the time of a time-terminated test that allows one failure fewer.

Any argument may be an array: the answer is then an array of the arguments’ broadcast shape.

Parameters:

  • mtbf (float) – The mean time between failures to demonstrate, positive.

  • failures (int, optional) – The failures the test allows, by default 0; with failure_terminated, the failure it stops at, from 1.

  • alpha_ci (float, optional) – Keyword only: the consumer’s risk, by default 0.05 (95% confidence).

  • failure_terminated (bool, optional) – Keyword only: whether the test stops at its failures-th failure rather than at a time, by default False.

Returns:

The total test time, in the MTBF’s units.

Return type:

float

Raises:

ValueError – If an argument is out of range.

Examples

With no failures, about 3 MTBFs of testing demonstrate the MTBF at 95% confidence:

>>> from surpyval.test_planning import mtbf_test_time
>>> round(mtbf_test_time(1000.0), 1)
2995.7
>>> round(mtbf_test_time(1000.0, failures=2), 1)
6295.8
>>> round(mtbf_test_time(1000.0, 3, failure_terminated=True), 1)
6295.8

surpyval.test_planning.demonstration_plan(reliability: float, good_reliability: float, *, alpha_ci: float = 0.05, producer_risk: float = 0.2, n: int | None = None, test_multiple: float = 1.0, shape: float | None = None, max_failures: int = 1000, mission_time: float | None = None) → DemonstrationPlan

The smallest attribute test that demonstrates a reliability and that a good design passes.

A plan’s consumer’s risk is the chance that a design of the target reliability passes it, at most alpha_ci; its producer’s risk is the chance that a design of good_reliability, which should pass, fails it, at most producer_risk. A test allowing no failures keeps the first with the fewest units, but often fails a good design: allowing failures, with more units, keeps both. For each number of failures allowed, from none, the fewest units that keep the consumer’s risk (demonstration_sample_size()) pass the good design most often, and the first of those plans that keeps the producer’s risk tests the fewest units of all.

Given n, the test length is searched instead, with the lifetime’s Weibull shape: the shortest test of n units that keeps both risks (each failure allowed takes a longer test, as demonstration_test_multiple() gives it).

Parameters:

  • reliability (float) – The reliability to demonstrate over one mission, in (0, 1).

  • good_reliability (float) – The reliability of a design that should pass, more than reliability and less than 1.

  • alpha_ci (float, optional) – Keyword only: the most consumer’s risk, by default 0.05 (95% confidence).

  • producer_risk (float, optional) – Keyword only: the most chance of failing a good design, in (0, 1), by default 0.2.

  • n (int, optional) – Keyword only: the number of units to test, to search the test length instead of the number of units (with shape).

  • test_multiple (float, optional) – Keyword only, without n: how many missions long each unit’s test is, by default 1.0 (another length needs shape).

  • shape (float, optional) – Keyword only: the Weibull shape of the lifetime, needed for a test longer or shorter than a mission, and with n.

  • max_failures (int, optional) – Keyword only: the most failures a plan may allow, by default 1000.

  • mission_time (float, optional) – Keyword only: the length of the mission, positive, to report each unit’s test length in time as well as in missions (unit_test_time).

Returns:

The plan: n, test_multiple and failures, and its risks (and unit_test_time, given mission_time).

Return type:

DemonstrationPlan

Raises:

ValueError – If an argument is out of range, good_reliability is no more than reliability, n is given without shape, or no plan within max_failures (or, given n, fewer failures than units) keeps both risks.

Examples

Demonstrating 90% reliability at 90% confidence, so that a design of 95% passes at least 80% of the time: a test of 22 units with no failures would pass that design only a third of the time, and the plan tests 128, allowing 8 to fail:

>>> from surpyval.test_planning import (
...     demonstration_pass_probability,
...     demonstration_plan,
... )
>>> round(demonstration_pass_probability(0.95, 22), 2)
0.32
>>> plan = demonstration_plan(0.9, 0.95, alpha_ci=0.1)
>>> plan.n, plan.failures
(128, 8)
>>> round(plan.consumer_risk, 3), round(plan.producer_risk, 3)
(0.097, 0.192)

Given the units, the test length is found instead: 20 units, for a wear-out shape of 2 and a 1000-hour mission, each run about 2820 hours, allowing 8 failures:

>>> plan = demonstration_plan(0.9, 0.95, alpha_ci=0.1, n=20,
...                           shape=2.0, mission_time=1000.0)
>>> round(plan.test_multiple, 3), round(plan.unit_test_time), plan.failures
(2.82, 2820, 8)
surpyval.test_planning.mtbf_demonstration_plan(mtbf: float, good_mtbf: float, *, alpha_ci: float = 0.05, producer_risk: float = 0.2, max_failures: int = 1000) → DemonstrationPlan

The shortest constant-failure-rate test that demonstrates an MTBF and that a good design passes.

The total test time and the failures it allows, for a time-terminated test, such that a design of the target mtbf passes with a chance of at most alpha_ci (the consumer’s risk) and one of good_mtbf fails with a chance of at most producer_risk: the fixed-length test plans of MIL-HDBK-781, for a discrimination ratio good_mtbf / mtbf. For each number of failures allowed, from none, the shortest test that keeps the consumer’s risk (mtbf_test_time()) passes the good design most often, and the first that keeps the producer’s risk is the shortest of all. Both risks are kept, where some of the handbook’s plans exceed one a little for a shorter test; those that keep both are these (plans XI-D, XV-D and XVII-D).

Parameters:

  • mtbf (float) – The MTBF to demonstrate, positive.

  • good_mtbf (float) – The MTBF of a design that should pass, more than mtbf.

  • alpha_ci (float, optional) – Keyword only: the most consumer’s risk, by default 0.05 (95% confidence).

  • producer_risk (float, optional) – Keyword only: the most chance of failing a good design, in (0, 1), by default 0.2.

  • max_failures (int, optional) – Keyword only: the most failures a plan may allow, by default 1000.

Returns:

The plan: test_time and failures, and its risks.

Return type:

DemonstrationPlan

Raises:

ValueError – If an argument is out of range, good_mtbf is no more than mtbf, or no plan within max_failures keeps both risks.

Examples

Demonstrating an MTBF of 1000 hours at 90% confidence, so that a design of 2000 passes at least 80% of the time (a discrimination ratio of 2): the test runs about 14,200 unit hours, and passes with at most 9 failures:

>>> from surpyval.test_planning import mtbf_demonstration_plan
>>> plan = mtbf_demonstration_plan(1000.0, 2000.0, alpha_ci=0.1)
>>> round(plan.test_time), plan.failures
(14206, 9)
>>> round(plan.consumer_risk, 3), round(plan.producer_risk, 3)
(0.1, 0.18)

A sequential test of an MTBF at a constant failure rate (Wald’s sequential probability ratio test).

surpyval.test_planning.accelerated_test_plan(distribution: Any, life_model: Any, life_params: Any, shape: float, *, use_stress: float, high_stress: float, n: int, censor_time: float, levels: int = 2, allocation: Sequence[float] | None = None, middle_fraction: float = 0.2, p: float = 0.1, alpha_ci: float = 0.05) → AcceleratedTestPlan

The accelerated life test that estimates a quantile at the use stress most precisely, with the highest stress fixed.

The test runs n units until censor_time at levels stresses, the highest high_stress and the others equally spaced between it and a lowest stress, on the scale of the planned log life (for the log-linear life models, equally spaced in log V for the power law and in 1 / V for Arrhenius). The lowest stress, and the share of units at it, are chosen to minimise the large-sample variance of the estimated quantile at use_stress:

  • with two levels, the statistically optimum plan (Nelson and Kielpinski, 1976; Meeker and Escobar, section 20.3);

  • with three or more, a compromise plan (Meeker and Hahn, 1985): middle_fraction of the units are shared equally among the middle stresses, which make the plan robust to a curved life-stress relation, at a small cost in precision;

  • with allocation, the shares at each stress, lowest first, are fixed ((4/7, 2/7, 1/7), the 4:2:1 plan), and only the lowest stress is chosen.

Parameters:

  • distribution (surpyval.Weibull or surpyval.LogNormal) – The lifetime distribution.

  • life_model (life model) – A single-stress life model from surpyval.life_models.

  • life_params (dict or sequence of float) – The life model’s planning values, by name or in its order.

  • shape (float) – The planning value of the shape: the Weibull’s beta or the lognormal’s sigma.

  • use_stress (float) – Keyword only: the stress to estimate the quantile at.

  • high_stress (float) – Keyword only: the highest stress the test may use, beyond which the failure mechanism could change.

  • n (int) – Keyword only: the number of units.

  • censor_time (float) – Keyword only: when the test stops.

  • levels (int, optional) – Keyword only: the number of stresses, at least 2, by default 2.

  • middle_fraction (float, optional) – Keyword only: with three or more levels and no allocation, the share of the units at the middle stresses, by default 0.2.

  • p (float, optional) – Keyword only: the probability of the quantile, by default 0.1 (the B10 life).

  • alpha_ci (float, optional) – Keyword only: the significance level of the interval, by default 0.05.

The power, events or units of a log-rank (or Cox) test of a hazard ratio between two groups, under proportional hazards.

Give the power to find the size; give the size (events, or n with event_probability) to find the power. Exactly one of power and the size is left None.

The events needed are Schoenfeld’s (1983), \(d = (z_{1 - \alpha / 2} + z_{\text{power}})^2 / (\pi (1 - \pi) (\ln \text{HR})^2)\), with \(\pi = r / (1 + r)\) the share of the units in the first group, or Freedman’s (1982), \(d = (z_{1 - \alpha / 2} + z_{\text{power}})^2 (r \text{HR} + 1)^2 / (r (\text{HR} - 1)^2)\) with method="freedman" (lifelines’ sample_size_necessary_under_cph and power_under_cph). The units are the events, unrounded, shared out in the ratio ratio and divided by each group’s chance of an event during the study; the power at given units uses their expected events, n1 * p1 + n2 * p2.

A difference planned as a ratio of mean lives maps to a hazard ratio only through the shape: for exponential lives a mean life r times as long is a hazard ratio of 1 / r, and for Weibull lives with a common shape beta, r ** -beta (a 30% longer mean life is 1 / 1.3 for exponential lives, 1.3 ** -2 for a shape of 2). Where the shape is known, mean_ratio_design() plans the exact test of the means themselves.

A group-sequential design for a normal test statistic.

A study looked at looks times can stop at a look as soon as the difference sought is clear (the efficacy boundary), or as soon as it is clearly not coming (the futility boundary). Looking more than once gives more chances of a false finding, so each look is held to a stricter level than the overall alpha_ci; the design chooses those levels so that the overall chance stays alpha_ci, and the maximum information so that the power stays power. The price is a little more information at most (the inflation factor); the gain is a smaller expected amount, because the study often stops early.

The design is on the scale of information fractions, for any test whose statistic is approximately normal with independent increments (a log-rank or Cox score test, a difference of means or of proportions): logrank_group_sequential() gives the events of a log-rank test, and GroupSequentialDesign.max_information() the information for a difference on the statistic’s scale.

The efficacy boundary is one of

  • the classical shapes: "obrien-fleming" (\(b_k = C / \sqrt{t_k}\), strict early, close to the fixed test’s level at the end), "pocock" (the same \(C\) at every look), "wang-tsiatis" (\(b_k = C t_k^{\Delta - 1/2}\), with \(\Delta\) the efficacy_parameter: 0 is O’Brien-Fleming’s, 0.5 Pocock’s), "haybittle-peto" (efficacy_parameter, 3 by default, at the interim looks, and the last look’s set to give exactly the level);

  • alpha-spending functions (Lan and DeMets 1983), which spend the level \(\alpha(t)\) by information fraction \(t\) and so allow looks at other times than planned (update): "lan-demets-obrien-fleming" (\(2 - 2 \Phi(z_{1 - \alpha / 2} / \sqrt{t})\), the default), "lan-demets-pocock" (\(\alpha \ln(1 + (e - 1) t)\)), "hwang-shih-decani" (\(\alpha (1 - e^{-\gamma t}) / (1 - e^{-\gamma})\), \(\gamma\) the parameter, -4 by default) and "kim-demets" (\(\alpha t^\rho\), \(\rho\) the parameter, 3 by default). A two-sided design spends \(\alpha / 2\) on each side with these, as R’s gsDesign and rpact do.

A futility boundary spends the type II error 1 - power with one of the spending functions, under the alternative (beta spending); the maximum information is then the one at which the two boundaries meet at the last look. Binding (the study must stop when it crosses) lets the efficacy boundary be a little lower; non-binding (the default) keeps the level if the study goes on regardless, and is the usual choice. Futility boundaries are for one-sided designs.

Parameters:

  • looks (int or sequence of float, optional) – The number of equally spaced looks, by default 3, or the information fraction of each, increasing and ending at 1.

  • power (float, optional) – The chance of stopping for efficacy when the difference is there, by default 0.8.

  • alpha_ci (float, optional) – Keyword only: the significance level, by default 0.05 (for a two-sided design, both sides together).

  • alternative (str, optional) – Keyword only: "two-sided" (the default; symmetric boundaries) or "one-sided".

  • efficacy (str, optional) – Keyword only: the efficacy boundary, by default "lan-demets-obrien-fleming".

  • efficacy_parameter (float, optional) – Keyword only: Wang-Tsiatis’ \(\Delta\) (required), Haybittle-Peto’s interim z, Hwang-Shih-DeCani’s \(\gamma\), Kim-DeMets’ \(\rho\).

  • futility (str, optional) – Keyword only: a spending function for a futility boundary, or None (the default) for none.

  • futility_parameter (float, optional) – Keyword only: the futility spending function’s parameter.

  • binding (bool, optional) – Keyword only: whether the futility boundary binds, by default False.

Return type:

GroupSequentialDesign

Raises:

ValueError – If an argument is out of range, or a combination is not built (futility on a two-sided design; binding futility with a classical efficacy boundary).

Examples

Three equally spaced looks at the two-sided 5% level, with O’Brien-Fleming-type spending:

Stopping early because the difference looked large makes the naive estimate (z / sqrt(t)) too large on average; the median-unbiased estimate is the drift at which the result seen is the median result, and the interval the drifts at which it is the alpha_ci / 2 and 1 - alpha_ci / 2 quantiles. update(timing: ArrayLike) → GroupSequentialDesign

The design re-computed for the information fractions the looks actually came at.

Information rarely arrives exactly as planned. With a spending function the boundaries can be re-computed at the fractions observed: give every look, those done and those still planned, as fractions of the planned maximum information. The last is the final look and spends what is left of the level, wherever it falls (above 1 if the study ran over). The levels spent at the looks already done are those of their fractions, so the earlier boundaries stay as they were used if their fractions are kept. A futility boundary is re-computed at the planned drift, and the last look’s futility boundary is its efficacy boundary; the power changes, and is reported.

Classical boundaries (O’Brien-Fleming, Pocock, Wang-Tsiatis, Haybittle-Peto) hold their level only at the planned looks, so they are not re-computed: plan with a spending function to keep this freedom.

Examples

>>> from surpyval.test_planning import group_sequential_design
>>> design = group_sequential_design(3, alternative="one-sided",
...                                  alpha_ci=0.025)
>>> actual = design.update([0.4, 0.7, 1.0])
>>> actual.efficacy_z.round(3).tolist()
[3.357, 2.445, 2.0]
surpyval.test_planning.boundary_crossing(timing: ArrayLike, lower: ArrayLike, upper: ArrayLike, drift: float = 0.0, *, r: int = 32) → tuple[NDArray, NDArray]

The chances of first crossing each look’s boundaries.

For looks at information fractions timing (t_k = I_k / I_max), a statistic Z_k with mean drift * sqrt(t_k), unit variance and corr(Z_j, Z_k) = sqrt(t_j / t_k): the chance of stopping at look k above upper[k] (or below lower[k]), having stayed between the boundaries at every look before. Computed by recursive numerical integration (Jennison and Turnbull 2000, chapter 19), not by simulation.

Parameters:

  • timing (array-like) – The information fractions of the looks, increasing, in (0, 1] (the last may differ from 1 when used to evaluate a design whose information ran over or short).

  • lower (array-like) – The boundaries at each look; -inf or inf for none.

  • upper (array-like) – The boundaries at each look; -inf or inf for none.

  • drift (float, optional) – theta sqrt(I_max), the mean of the statistic at full information; 0 (the default) is the null hypothesis.

  • r (int, optional) – Keyword only: the grid size, 12 r - 3 points per look, by default 32.

Returns:

(upper, lower) – The chance of first crossing the upper boundary, and the lower, at each look.

Return type:

tuple of arrays

Examples
