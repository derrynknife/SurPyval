Parametric Recurrence Model

The fitted model returned by the Poisson-process fitters (HPP, CrowAMSAA, Duane, CoxLewis) and by their from_params. It evaluates the fitted process – the cumulative intensity cif (which for a Poisson process is also the mean cumulative function, mcf), the intensity iif, the instantaneous MTBF mtbf and the inverse inv_cif – with confidence bounds (cif_cb, iif_cb, mtbf_cb, with Crow’s exact bounds on the demonstrated MTBF, and param_cb), likelihood inference (log_likelihood, aic, bic, covariance, standard_errors), goodness-of-fit diagnostics (residuals, trend_test, cramer_von_mises), simulation of new histories and plotting. Models built with from_params or fitted with how="MSE" have no likelihood, so the inference methods raise.

The base class of the Poisson-process fitters, which defines the functions every intensity model provides, is CountingProcess, documented at the end of this page.

class surpyval.recurrent.parametric.parametric_recurrence.ParametricRecurrenceModel

Bases: ReleaseTimeMixin, GrowthAnswersMixin, ParameterBoundsMixin, DiagnoseMixin, SerialisableMixin, RecurrenceSimulationMixin, LikelihoodInferenceMixin

A class for holding the parameters, data, and useful methods for a fitted parametric recurrence model. This is the result of the fit calls from the counting distributions.

When fitted by maximum likelihood the model also carries the likelihood- inference behaviour (log_likelihood, aic, bic, standard_errors) from LikelihoodInferenceMixin. Models built by from_params or fitted by how="MSE" carry no likelihood, so those methods raise.

Example

>>> from surpyval import Exponential
>>> from surpyval.recurrent import HPP
>>> import numpy as np
>>> np.random.seed(1)
>>> x = Exponential.random(10, 1e-3).cumsum()
>>> model = HPP.fit(x)
aic() → float

Akaike’s information criterion, \(2k - 2\ln L\), with k the number of fitted parameters. Lower is better. Call it, model.aic(), as on every other fitted model.

Changed in version 0.23: aic is a method, as on every other model (#572); it was a property.

aic_c() → float

The small-sample corrected AIC, aic() + (2k^2 + 2k) / (n - k - 1), with the k of aic() and the n of bic(); nan where n <= k + 1 (corrected_aic), as on every other model (#605).

bic() → float

The Bayesian information criterion, \(k \ln n - 2\ln L\), with n the number of observed events the model was fitted to: exact, left- and interval-censored, the last two adding the number of events they hold. End-of-observation rows do not add to it, and with no observed event it is the number of rows – the rule of BIC everywhere in SurPyval (see bic_sample_size()). Lower is better. Call it, model.bic(), as on every other fitted model.

Changed in version 0.23: bic is a method, as on every other model (#572); it was a property.

count_terminated_simulation(events: int, items: int = 1, random_state: int | None = None) → Any

Simulate count-terminated recurrence data based on the fitted model.

Parameters:

  • events (int) – Each sequence is simulated to its events + 1-th event, and the returned MCF is kept only where it is below events (beyond that the items are dropping out of observation).

  • items (int, optional) – Number of items (or sequences) to simulate. Default is 1.

  • random_state (int or numpy.random.Generator, optional) – Seed for a reproducible simulation. When None (default) the numpy global RNG is used.

Returns:

An NonParametricCounting model built from the simulated data.

Return type:

NonParametricCounting

Raises:

ValueError – If the model’s expected number of events over all time, cif(inf), is finite (a Cox-Lewis with beta < 0): a sequence may then never reach its events + 1-th event. Use time_terminated_simulation() for such a model.

count_terminated_simulation_data(events: int, items: int = 1, random_state: int | None = None) → Any

Simulate count-terminated recurrence data and return the raw events.

Unlike count_terminated_simulation() (which returns the fitted NonParametricCounting MCF), this returns the simulated event data itself, ready to be refitted or inspected via .x/.i/.c/ .n.

Parameters:

  • events (int) – Each sequence is simulated to its events + 1-th event (see the notes).

  • items (int, optional) – Number of items (or sequences) to simulate. Default is 1.

  • random_state (int or numpy.random.Generator, optional) – Seed for a reproducible simulation.

Returns:

The simulated recurrence data in xicn format.

Return type:

EventHistoryData

Raises:

ValueError – If the model’s expected number of events over all time, cif(inf), is finite (a Cox-Lewis with beta < 0): a sequence may then never reach its events + 1-th event.

Notes

Count termination is a failure-terminated (Type II) scheme: each item is observed until its events + 1-th event, so its observation window is the random time of that last event and every event is exact (c = 0). Parametric fits handle this correctly – the interarrival/intensity likelihood ends at the last observed event and the MLE is consistent. The nonparametric MCF, however, is only reliable up to roughly events recurrences: beyond that the at-risk set is depleted and the curve is biased (which is why count_terminated_simulation() trims to mcf_hat < events). For a fixed-window observation scheme, use time_terminated_simulation_data(), which right-censors each item at T.

cramer_von_mises(n_boot: int = 200, random_state: int | None = None) → Any

Cramer-von Mises goodness-of-fit test of the fitted intensity.

Conditional on the number of events an item shows in its observation window, the transformed times [cif(t) - cif(entry)] / [cif(close) - cif(entry)] are iid U(0, 1) when the fitted intensity is the true one; the Cramer-von Mises statistic measures their departure from uniformity (for the power-law process this is the construction behind Crow’s goodness-of-fit test). Because the parameters were estimated from the same data, the p-value is computed by a parametric bootstrap: data is simulated from the fitted model over the same observation windows, refitted, and the statistic recomputed. Failure-truncated items (no explicit window close) are approximated in the bootstrap by a window fixed at their last observed event.

Parameters:

  • n_boot (int, optional) – Number of bootstrap replicates for the p-value. Default is 200.

  • random_state (int or numpy.random.Generator, optional) – Seed for a reproducible p-value.

Returns:

The observed statistic and its bootstrap p-value.

Return type:

GoodnessOfFitResult

diagnose(alpha: float = 0.05, columns: Sequence[str] | None = None, *, n_boot: int | None = None, random_state: Any = None, **options: Any) → Diagnosis

Check the model’s assumptions, fit and influential points, and say what to do about any that fail.

Runs the checks this kind of model calls for (for a Cox model: proportional hazards, the functional form of each continuous covariate, influence and outliers; see Model Diagnostics) and returns a report: d.table, one row per check with its test, statistic, p-value, verdict ("ok", "warn" or "fail") and covariates; d.advice, plain-English remedies that each name the SurPyval feature that applies them; d.plot(), the visual checks (matplotlib is only imported then); d.ok, True if nothing failed; d.raise_if_failed() for pipelines; and d.to_dict().

A test fails when its p-value is below alpha, and warns when it is below 2 * alpha (borderline) or could not be computed. Each row is judged at alpha on its own, so with many rows some fail by chance even when every assumption holds.

Parameters:

  • alpha (float, optional) – The level each test is judged at. Default 0.05.

  • columns (str or list of str, optional) – The covariates to check, named as summary() names them (the DataFrame or formula columns, else coef_0, …); all of them by default. A joint (GLOBAL) test still covers every covariate.

  • n_boot (int, optional) – For the families whose tests resample (a univariate distribution’s bootstrap goodness-of-fit tests): the number of bootstrap refits; None is the family’s default. Other families ignore it.

  • random_state (optional) – The seed of those resamples (SurPyval’s one seed rule: None draws from numpy’s global generator).

  • **options – Options of the model’s family, named in Model Diagnostics: for an accelerated life model, use_stress, the stress the model is to predict at (a number, or one per stress column), whose distance from the tested stresses the report screens. A family refuses an option it does not take.

Returns:

See surpyval.diagnostics.Diagnosis.

Return type:

Diagnosis

Raises:

  • NotImplementedError – For a model whose family’s diagnostics are not built yet, saying what to check it with meanwhile; for an option of the model the checks do not support yet; and for a kind of model the checks do not cover by design (a discrete distribution, a parametric regression with a custom link, …), saying what to use instead.

  • ValueError – For a model the checks cannot be run on (one restored with from_dict, which has no data), saying what to do.

Examples

>>> from surpyval import CoxPH
>>> from surpyval.datasets import load_rossi_static
>>> df = load_rossi_static()
>>> df["censored"] = 1 - df["arrest"]
>>> model = CoxPH.fit_from_df(
...     df, x_col="week", c_col="censored", Z_cols=["fin", "age"]
... )
>>> d = model.diagnose()
>>> d.ok
False
>>> d.table[["check", "transform", "covariates", "verdict"]].head(3)
                  check transform covariates verdict
0  proportional_hazards        km     (fin,)      ok
1  proportional_hazards        km     (age,)    fail
2  proportional_hazards        km (fin, age)    fail

mtbf_cb(x: ArrayLike, alpha_ci: float = 0.05, bound: str = 'two-sided', method: str = 'wald') → ndarray

Confidence bounds on the instantaneous MTBF (mtbf()) at x. A lower bound on the MTBF is the reciprocal of an upper bound on the intensity, and the other way round; this method does the flipping, so bound="lower" is a lower bound on the MTBF.

The deliverable of a reliability growth test is usually the lower bound on the demonstrated MTBF, mtbf_cb(T, bound="lower", method="crow") at the end of the test T, compared with the requirement.

Parameters:

  • x (array_like) – Values at which to compute the confidence bounds. With method="crow" every value must be the end of the test.

  • alpha_ci (float, optional) – The total tail probability of the bound(s). Default is 0.05.

  • bound ({'two-sided', 'lower', 'upper'}, optional) – Two-sided bounds are returned as an (len(x), 2) array with columns [lower, upper]; one-sided bounds have the shape of x.

  • method ({'wald', 'crow'}, optional) –

    "wald" (default): the reciprocals of the delta-method bounds of iif_cb(), for any model and any x.

    "crow": the exact bounds of Crow (1982), which MIL-HDBK-189C tabulates, for a CrowAMSAA model fitted by maximum likelihood, at the end of the test only: M_hat * L and M_hat * U, with coefficients that depend only on the number of failures N and the level. Two designs have them:

    • time terminated: every item observed from 0 to the same time T (each ends in a c = 1 row at T, or the data are truncated at T), with N >= 1 failures in all. The bounds invert the test of the MTBF conditional on the sufficient statistic of the shape, so they are exact in the sense of a discrete test: they hold at least their level (with few failures, a lower bound at 90% covers about 92% to 97% of the time). With N = 1 the upper bound is infinite.

    • failure terminated: one item, observed to its N-th failure (N >= 2) with no c = 1 row. Then M_hat / M is a pivot (the product of independent Gamma(N) and Gamma(N - 1) variables over N^2) and the bounds hold their level exactly.

    Other data (delayed entry, different end times, interval or left censoring, several failure-terminated items) have no exact bound, and "crow" raises; use "wald".

Returns:

The confidence bounds on the instantaneous MTBF.

Return type:

numpy array

References

Crow, L. H. (1982), “Confidence interval procedures for the Weibull process with applications to reliability growth”, Technometrics 24(1), 67-72.

MIL-HDBK-189C (2011), “Reliability Growth Management”, Section 5.

Examples

A growth test of one prototype, stopped at 2000 hours. The 80% lower bound on the demonstrated MTBF, against a requirement of 150 hours:

>>> from surpyval.recurrent import CrowAMSAA
>>> x = [40, 110, 210, 340, 500, 690, 920, 1180, 1480, 1800, 2000]
>>> c = [0] * 10 + [1]
>>> model = CrowAMSAA.fit(x, c=c)
>>> lower = model.mtbf_cb(2000.0, alpha_ci=0.2, bound="lower",
...                       method="crow")
>>> round(float(lower), 1)
196.9
>>> round(float(model.mtbf_cb(2000.0, alpha_ci=0.2, bound="lower")), 1)
205.9

next_failure_qf(p: ArrayLike, age: ArrayLike | None = None) → ndarray

The time ahead of each unit’s age by which it has its next event with probability p: the quantile function of the time to its next event, \(\Lambda^{-1}(\Lambda(t) - \log(1 - p)) - t\), the inverse of next_failure_sf(). Found from the cumulative intensity, the time is exact to about the double’s rounding of the age \(t\) (an absolute error near \(10^{-16} t\)), which a tiny gap after a long life carries.

Parameters:

  • p (array_like) – Probabilities in [0, 1]. p = 0 gives 0 and p = 1 inf; a value outside [0, 1] gives nan, with a warning. Where the cumulative intensity is bounded (a falling Cox-Lewis intensity) a p it never reaches gives inf: the unit may never have another event.

  • age (array_like, optional) – Each unit’s time now (since new). By default the units are the fitted data’s items, each at the end of its observation.

Returns:

(units, len(p)), one row per unit; (units,) for a scalar p.

Return type:

numpy.ndarray

Examples

For a homogeneous Poisson process the time to the next event is exponential whatever the age, \(-\log(1 - p) / \lambda\):

>>> from surpyval.recurrent import HPP
>>> HPP.from_params([0.1]).next_failure_qf(0.5, age=[0.0, 50.0])
array([6.93147181, 6.93147181])
next_failure_random(size: int, age: ArrayLike | None = None, *, random_state: Any = None) → ndarray

Draw each unit’s time to its next event, ahead of its age: size draws per unit, each next_failure_qf() at one uniform u (the uniforms fill the result row by row), i.e. \(\Lambda^{-1}(\Lambda(t) - \log(1 - u)) - t\).

Each event is a minimal repair, so a unit’s next age is its age plus the draw: stepping age forward this way reproduces time_terminated_simulation() in distribution.

Parameters:

  • size (int) – The number of draws for each unit.

  • age (array_like, optional) – Each unit’s time now (since new). By default the units are the fitted data’s items, each at the end of its observation.

  • random_state (int or numpy.random.Generator, optional) – Seed or generator for a reproducible draw (keyword only); by default one seeded from numpy’s global stream, so np.random.seed makes the draw reproducible.

Returns:

(units, size): one row per unit.

Return type:

numpy.ndarray

Examples

>>> from surpyval.recurrent import CrowAMSAA
>>> model = CrowAMSAA.from_params([10, 1.5])
>>> model.next_failure_random(3, age=[0.0, 100.0],
...                           random_state=1).round(3)
array([[ 8.011, 20.824,  2.894],
       [ 6.165,  0.786,  1.157]])
next_failure_sf(x: ArrayLike, age: ArrayLike | None = None) → ndarray

The chance that each unit runs a further x from its age without an event: the survival function of the time to its next event, \(\exp(-[\Lambda(t + x) - \Lambda(t)])\).

Each event of these processes is a minimal repair, so the time to the next one depends only on the time now \(t\), not on the events before it. The names and arguments are those of RenewalModel.next_failure_sf, so either kind of model can be stepped forward the same way.

Parameters:

  • x (array_like) – Times ahead of now (at least 0).

release_time(test_cost: float, fix_cost: float, field_cost: float, *, life: float | None = None, reliability: float | None = None, mission: float | None = None, within: float = 0.01) → dict

The testing time at which to release for the least expected total cost (Okumoto and Goel 1980), optionally no earlier than a reliability target is met.

Releasing after testing to T is expected to cost fix_cost * cif(T) + field_cost * (cif(life) - cif(T)) + test_cost * T: the faults found in testing, those left to be found in use, and the testing itself. Testing pays while the intensity is above test_cost / (field_cost - fix_cost), so the cheapest release is when it has fallen to that level (0 where it never is above it: release without testing).

Parameters:

  • test_cost (float) – The cost of one unit of testing time (the model’s unit), above 0. Any currency, the same for the three costs.

  • fix_cost (float) – The cost of a fault found and fixed in testing.

  • field_cost (float) – The cost of a fault found in use, above fix_cost.

  • life (float, optional) – The time on the test’s clock (testing plus use) at which the software goes out of service. By default it is used for ever, which needs a model with a finite number of faults; a model without one (MusaOkumoto, CrowAMSAA) raises a ValueError asking for it. Keyword only, as those below.

  • reliability (float, optional) – A target the release must meet as well: the chance reliability of running a mission of use without a failure (as time_to_reliability()). The release is then the later of the cheapest time and the time the target is met.

  • mission (float, optional) – A target the release must meet as well: the chance reliability of running a mission of use without a failure (as time_to_reliability()). The release is then the later of the cheapest time and the time the target is met.

  • within (float, optional) – The share of the least cost that counts as near it, for the band of near-best times. Default 0.01 (1%).

Returns:

"time": the release time, on the model’s clock (subtract the testing done to get what is left to do); "cost": the expected total cost of releasing then; "binding": "cost", "reliability" (the target sets the time) or "life" (testing would pay to the end of the life); "cost_time" and "least_cost": the cheapest time and its cost, whatever the target; "reliability_time": the time the target is met (None without one); "band": (earliest, latest), the release times whose expected cost is within within of the least. A wide band says the cost hardly depends on the day chosen.

Return type:

dict

Raises:

ValueError – Where field_cost is not above fix_cost, or the fitted intensity never falls to the level at which testing stops paying (a constant or rising intensity), saying which.

References

Okumoto, K. and Goel, A. L. (1980), “Optimum release time for software systems based on reliability and cost criteria”, Journal of Systems and Software 1, 315-318.

Examples

A Goel-Okumoto model with 100 faults: a day of testing costs 50, a fault 10 to fix in testing and 500 in the field. The cheapest release is at log(a b (c2 - c1) / c3) / b:

>>> from surpyval.recurrent import GoelOkumoto
>>> model = GoelOkumoto.from_params([100, 0.05])
>>> plan = model.release_time(50, 10, 500)
>>> round(plan["time"], 2), round(plan["cost"])
(77.84, 5892)
>>> [round(t, 1) for t in plan["band"]]
[71.3, 85.1]

With a 95% chance of 10 days without a failure required as well, the release waits for the target:

>>> plan = model.release_time(50, 10, 500, reliability=0.95,
...                           mission=10.0)
>>> round(plan["time"], 2), plan["binding"]
(132.85, 'reliability')

residuals(kind: str = 'cumulative_hazard') → ndarray

Residual diagnostics for the fitted model, from the time-rescaling theorem.

Parameters:

kind ({'cumulative_hazard', 'pit', 'martingale'}, optional) –

'cumulative_hazard' returns the rescaled interarrival times cif(t_k) - cif(t_{k-1}) of every observed event (pooled across items); see below for how far they are iid Exp(1). 'pit' applies the probability integral transform 1 - exp(-e) to those residuals (U(0, 1) under the same conditions). 'martingale' returns one residual per (sorted-unique) item: its observed event count minus the count the model expects over its observation window; positive values mean the item saw more events than predicted.

Only complete gaps (event to event) are returned. When an item’s observation ends at a window close rather than at an event, its final gap is censored and left out, and that selection makes the returned residuals smaller than Exp(1) on average – noticeably so with few events per item (a mean near 0.66 with about three events per item). So they are exactly iid Exp(1) only for failure-truncated items; otherwise read a Q-Q plot against Exp(1) with this downward bias in mind, or use cramer_von_mises, which conditions on each item’s window correctly.

Returns:

The residuals.

Return type:

numpy array

class surpyval.recurrent.parametric.counting_process.CountingProcess

Bases: FitterRepr, RecurrentDataFrameMixin, ABC

Abstract base class for parametric counting-process intensity models.

A counting process N(t) counts the number of events observed up to time t. Every parametric counting process in surpyval is described by functions of time and its parameters:

  • iif the instantaneous intensity function (the rate of events),

  • cif the cumulative intensity function (the expected number of events by t, i.e. the integral of iif from the origin), and

  • log_iif the natural logarithm of the instantaneous intensity, used directly in the log-likelihood.

Concrete subclasses also expose a parameter_names attribute listing the names of the model’s parameters. This shared base lets fitters such as ProportionalIntensityNHPP verify, with a simple isinstance check, that the intensity model handed to them really is a counting process.

Examples

It is abstract; the intensity models (HPP, CrowAMSAA, Duane, CoxLewis …) are instances of it:

>>> import numpy as np
>>> from surpyval.recurrent import CountingProcess, CrowAMSAA
>>> isinstance(CrowAMSAA, CountingProcess)
True
>>> CrowAMSAA.parameter_names
['alpha', 'beta']
>>> x = [10, 19, 27, 34, 40, 45, 49, 52, 54]
>>> model = CrowAMSAA.fit(x)
>>> CrowAMSAA.cif(np.array([30.0, 60.0]), *model.params).round(4)
array([ 2.7808, 11.1094])

classmethod fit_from_df(df: pd.DataFrame, x_col: str, i_col: str | None = None, c_col: str | None = None, n_col: str | None = None, tl_col: str | None = None, tr_col: str | None = None, *, a_col=None, unit=None, **fit_options: Any) → Any

Fit to an event log held in the columns of a pandas.DataFrame.

The column names are passed in place of the arrays fit() takes, with the names every recurrent fit_from_df uses (CauseSpecificNHPP.fit_from_df too); every other fit() option (how, dist, init, windows, …) is passed to it unchanged. The columns are handed to fit() as they are, so the result, and the refusal of a missing value in a unit’s history, is that of fit() on the same arrays.

Parameters:

  • df (pandas.DataFrame) – The event log.

  • x_col (str) – Column of event (and end-of-observation) times.

  • i_col (str, optional) – Column of item / unit ids. Defaults to a single item.

  • c_col (str, optional) – Column of censoring flags (0 an event, 1 the end of a unit’s observation).

  • n_col (str, optional) – Column of event counts per row.

  • tl_col (str, optional) – Columns of per-row left / right truncation (the start and end of each unit’s observation window), for a fitter whose fit() takes tl / tr.

  • tr_col (str, optional) – Columns of per-row left / right truncation (the start and end of each unit’s observation window), for a fitter whose fit() takes tl / tr.

  • a_col (str, optional) – Column of terminal flags: 1 where the row’s event ended the unit’s history for good, 0 or blank elsewhere (a blank event on a unit’s last row is read as 1). It does not change the fit: the model’s notes say that each terminal event is fitted as an event followed by the end of that unit’s observation.

  • **fit_options – Every other option of fit().

Returns:

The model fit() returns.

Return type:

model

Raises:

  • ValueError – If df is not a DataFrame, a name is not one of its columns, or a column is given that fit() has no argument for.

  • TypeError – If a column is named with fit()’s argument (c= for c_col=, likewise x, i, n, and tl / tr given a column label); a number for tl / tr is passed on to fit().
