Parametric Model

The fitted model returned by every parametric distribution’s fit (and by from_params). It holds the fitted parameters params (with gamma, lfp_p and f0 for offset, limited-failure and zero-inflated models), the data it was fitted to, and the parameter covariance, and whether a maximum-likelihood fit reached a verified maximum (maximum), and provides the distribution’s functions at those parameters (sf, ff, df, hf, Hf, qf, cs, mean, var, moment, entropy, random, random_data), the same model with other parameters (with_params, extras), its bootstrap refits (bootstrap, a ParametricBootstrap), a maximum-likelihood fit’s reduced bias adjustment (rba), confidence bounds on those functions (cb, with method="pivotal" for a probability-plotting fit) and on the parameters (param_cb, and the joint region of two, likelihood_contour), the restricted mean survival time with its bounds (rmst, rmst_cb), information criteria (aic, aic_c, bic, neg_ll), probability plots and serialisation. How to use it is shown in Parametric SurPyval Modelling.

class surpyval.univariate.parametric.parametric.Parametric(dist: Any, method: str, data: Any, offset: bool, lfp: bool, zi: bool)

Bases: ParameterBoundsMixin, LikelihoodRatioMixin, InformationCriteriaMixin, DiagnoseMixin, SerialisableMixin, ParametricDistribution, PredictsRecordsMixin

Result of .fit() or .from_params() method for every parametric surpyval distribution.

Instances of this class are very useful when a user needs the other functions of a distribution for plotting, optimizations, monte carlo analysis and numeric integration.

maximum

Whether the fit’s answer is a maximum of the likelihood, and so whether its log-likelihood, aic, bic and aic_c and its standard errors mean what they say (principles 12 and 13):

  • "verified": a maximum-likelihood fit whose answer is verifiably a maximum (a zero gradient and a positive-definite Hessian), or exact (a closed form);

  • "unverified": a maximum-likelihood fit whose search did not reach a verified maximum; the parameters are the best point it found, and the fit warned so;

  • "no finite maximum": a maximum-likelihood fit to data on which the likelihood has no finite maximum (a parameter runs off to a limit of its range); the fit warned “No finite maximum”, and the parameters are where the search stopped;

  • "not applicable": the parameters do not come from maximising the likelihood – a fit by how="MPS", "MSE", "MPP" or "MOM", fit_from_ecdf, or a model built with from_params;

  • "unknown": a maximum-likelihood fit restored from a dictionary saved before the attribute existed.

fit_best() ranks a candidate by its criterion only when this is "verified", unless nothing else fitted.

Type:

str

hess_inv

The inverse Hessian of the negative log-likelihood at the fitted parameters, the distribution’s parameters’ block (the curvature of the likelihood, not a variance in general). For a fit with weights w it is that of the weighted log-likelihood with the weights as given (R’s naive.var), which is not the variance of the estimate: the bounds use the robust covariance, covariance(). Without weights the two are the same matrix. Use covariance() (or standard_errors()) for a variance. Not set on a model built with from_params, or on a weighted model saved by v0.26, which stored the robust covariance in its place. It covers the distribution’s parameters only (parameter_names), never lfp_p or f0; the covariance of every estimated parameter, named row by row, is covariance() with covariance_names.

Type:

ndarray

Examples

>>> import surpyval as surv
>>> model = surv.Weibull.fit([10, 12, 15, 17, 20, 25, 31])
>>> type(model).__name__
'Parametric'
>>> model.params.round(3)
array([20.881,  2.931])
>>> model.sf([10, 20]).round(4)
array([0.8909, 0.4143])
>>> model.maximum
'verified'

A model built from parameters has the same functions. With a limited failure population, one unit in ten never fails, so the mean life is infinite:

>>> lfp = surv.Weibull.from_params([20, 3], lfp_p=0.9)
>>> float(lfp.sf(1000.0).round(4)), lfp.mean(), lfp.extras
(0.1, inf, {'lfp_p': 0.9})
>>> lfp.maximum
'not applicable'
Hf(x: ArrayLike) → NDArray

The cumulative hazard function for a distribution using the parameters found in the .params attribute.

Parameters:

x (array like or scalar) – The values of the random variables at which the cumulative hazard function will be calculated

Returns:

Hf – The scalar value of the cumulative hazard function of the distribution if a scalar was passed. If an array like object was passed then a numpy array is returned with the value of the cumulative hazard function at each corresponding value in the input array.

Return type:

scalar or numpy array

Notes

It is -log sf(x). A zero-inflated model’s is -log(1 - f0) + H(x) from 0 on (its survival is (1 - f0) R(x)), so it stays finite far in the tail, where sf underflows to 0 (#710). A limited failure population’s is -log(1 - ff(x)) where ff is below 1/2, accurate where ff is tiny and sf rounds to 1 (#728); its survival stays above 1 - p in the upper tail.

Examples

>>> from surpyval import Weibull
>>> model = Weibull.from_params([10, 3])
>>> model.Hf(2)
np.float64(0.008000000000000002)
>>> model.Hf([1, 2, 3, 4, 5])
array([0.001, 0.008, 0.027, 0.064, 0.125])
>>> zi = Weibull.from_params([10, 3], f0=0.1)
>>> zi.Hf([0.0, 1000.0]).round(4)
array([1.0536e-01, 1.0000e+06])

The Corrected Aikake Information Criterion (AIC) for the model, if it was fit with the fit() method. Not available if fit with the from_params() method.

Returns:

aic_c – The Corrected AIC of the model

Return type:

float

>>> from surpyval import Weibull

>>> x = Weibull.random(100, 10, 3)
>>> model = Weibull.fit(x)
>>> model.aic_c()

Notes

The correction \((2k^2 + 2k)/(N - k - 1)\) uses the same sample size \(N\) as bic(): the number of observed failures (exact, left- or interval-censored, weighted by their counts), or the number of units when there is none. Right-censored units do not add to it. The correction only exists for \(N > k + 1\); otherwise the corrected criterion is undefined and nan is returned (the formula gave inf at \(N = k + 1\), and a value below aic() for smaller \(N\), which would have won a comparison).

Bayesian Information Criterion for Censored Survival Models.

Notes

The sample size \(d\) in the penalty \(k \ln d\) is the number of observed failures: every unit whose failure was observed, exactly or within a left- or interval-censored window, weighted by its count; right-censored units add nothing. Should that be zero, the number of units is used instead, so the criterion is always finite. Every model in SurPyval that reports a BIC counts \(d\) this way (see “Information criteria” in the Parametric Estimation guide).

bootstrap(n_boot: int = 200, random_state: Any = None) → Any

The model refitted to n_boot bootstrap resamples of its data: the other way, beside draws from covariance() through with_params(), to carry the fit’s uncertainty into anything built from it. It is the sound one for an offset fit (whose gamma has no row in the covariance) and for small samples, where the normal approximation behind the covariance is poor.

These are the refits behind the method="bootstrap" bounds (cb, quantile_cb, param_cb, mrl_cb, rmst_cb): the same n_boot and integer random_state give the same refits, which are kept on the model and reused. Each resample draws a failure time for every unit from the fitted model (within its truncation window) and censors it as the unit was censored; a fit with weights w is resampled by cases instead (the units drawn with replacement, each with its weight). Each refit has the model’s own options: offset, lfp, zi and fixed parameters.

Parameters:

  • n_boot (int, optional) – The number of refits. Defaults to 200, the bounds’ default; a thousand or more is usual for a final answer.

  • random_state (int or numpy Generator, optional) – The seed of the resamples.

Returns:

The kept refits (models), their parameters in the order of covariance_names (params; gamma beside it for an offset fit), and the counts of refits that failed (left out), had no finite maximum or an unverified one (kept, as the bounds keep them). A warning says so where more than a few did not reach a verified maximum.

Return type:

ParametricBootstrap

Raises:

ValueError – For a model without its data (built from parameters, or restored without them), a discrete distribution, or left- or interval-censored data, which a resample cannot reproduce; and for a weighted limited-failure or zero-inflated fit. Each message says to draw from the covariance instead.

Examples

>>> import numpy as np
>>> from surpyval import Weibull
>>> np.random.seed(1)
>>> model = Weibull.fit(Weibull.random(30, 10, 3))
>>> boot = model.bootstrap(100, random_state=1)
>>> boot.params.shape, boot.failed
((100, 2), 0)
>>> sf = [m.sf(8.0) for m in boot.models]
>>> float(np.round(np.std(sf), 2))
0.08
cb(x: ArrayLike, on: str = 'sf', alpha_ci: float = 0.05, bound: str = 'two-sided', method: str = 'wald', n_boot: int = 200, random_state: Any = None, n_sim: int = 9999) → NDArray

Confidence bounds of the on function at the alpha_ci level of significance. Can be the upper, lower, or two-sided confidence by changing value of bound.

Parameters:

  • x (array like or scalar) – The values of the random variables at which the confidence bounds will be calculated

  • on (('sf', 'ff', 'Hf', 'hf', 'df'), optional) – The function on which the confidence bound will be calculated. The Wald bounds on sf, ff and Hf come from one bound on the log cumulative hazard, log Hf = log(-log sf) (the “log-log” transform, on which a Weibull is a straight line in log time); those on hf and df are on the log scale (the logit scale for a discrete distribution, whose hazard and mass are probabilities), and are 0 where the rate is 0. Each x’s Wald bound is computed on its own. Where the delta-method variance is negative (the covariance is not positive definite) a Wald bound is nan, with a warning; where the function’s derivatives overflow at an x far in a tail, that x’s bound alone is nan, with a warning naming it. The Hf bound is on log Hf wherever the survival has underflowed (for the log-log families everywhere: it is the same bound), so it stays finite and contains the estimate there. The ff and Hf bounds are mapped from the band’s scale to their own, so they keep their digits in the left tail, where sf rounds to 1 (1 - sf and -log sf of its bound were 0). The Wald band on sf and ff rises (or falls) with x as the function does whenever the shape’s own Wald interval excludes 0; with fewer failures than that it can turn back in a tail, and the likelihood-ratio band (method="lr"), which is always monotone, is the one to use.

  • bound (('two-sided', 'upper', 'lower'), str, optional) – Compute either the two-sided, upper or lower confidence bound(s). Defaults to two-sided.

  • alpha_ci (scalar, optional) – The level of significance at which the bound will be computed.

  • method (('wald', 'lr', 'bootstrap', 'pivotal'), str, optional) – "wald" (default) propagates the parameter covariance through the on function by the delta method. For an offset model the covariance leaves the offset out (it is a threshold, whose likelihood is not regular), so the Wald bounds hold it at its estimate and are too narrow near it, with a warning saying so; "bootstrap" includes it (#645). "lr" gives a profile-likelihood (likelihood-ratio) band: at each x the bound is the extreme value of the on function over the parameter confidence region {theta : 2[nll(theta) - nll_hat] <= chi2} (the piece of it around the estimate), which is where the function’s own profile deviance reaches chi2; a band whose region reaches the edge of the function’s range (0 or 1 for sf) is that edge. The sf, ff and Hf bands are one band, so they agree exactly, except far in the upper tail, where sf has no room left (below 1e-308) and the Hf band is found on the scale of log Hf (the same extreme of the same region). The likelihood-ratio band is transformation-invariant and does not rely on a quadratic approximation, so it is usually better in small samples (Meeker and Escobar recommend it there), but it is computed pointwise and so is slower, and needs the original data (a model restored from to_dict(with_data=True) has it; one saved without it raises). For an offset, limited-failure or zero-inflated model the region is over every fitted parameter, gamma, lfp_p and f0 included, and the function is the model’s own; at a time before the estimated offset the band reaches below 1 wherever the region holds an offset below it. Where an offset model’s region reaches the first failure with its offset, where the likelihood is unbounded, the band at that level is nan, with a warning. Where the constrained search cannot find a bound from any start, that bound is nan, with a warning. "bootstrap" is the parametric bootstrap: the model is refitted to n_boot data sets simulated from it (each unit censored as it was, within its truncation window), and the bound is the bias-corrected percentile interval of the refits’ on function. It includes the uncertainty of every estimated parameter, an offset’s among them, and needs the original data, exact or right censored (truncated or not). A limited-failure or zero-inflated model is refitted with the same options; a unit drawn as never failing is censored as the units were, or at the last time in the data where its drawn censoring time is beyond it. The refits are kept on the model for each n_boot and integer random_state, so bounds at other x (and quantile_cb and param_cb) reuse them. "pivotal" is for a probability-plotting fit (how="MPP") of the Weibull, LogNormal, LogLogistic, Normal, Logistic, Gumbel, GumbelLEV or Exponential, and only for it: the Monte Carlo pivotal bound, from the fits of n_sim simulated standard samples of the same size and rank pattern by the same regression; exact for complete and type II censored samples, up to Monte Carlo error (see Parametric SurPyval Modelling, “Bounds for a probability-plotting fit”). It bounds sf, ff and Hf (one band, the inverse of quantile_cb’s), not hf or df.

  • n_boot (int, optional) – The number of bootstrap refits, with method="bootstrap". Defaults to 200.

  • random_state (int or numpy Generator, optional) – The seed of the bootstrap’s or the pivotal bound’s simulations; the pivotal fits are kept on the model for an integer seed, as the refits are.

  • n_sim (int, optional) – The number of simulated fits, with method="pivotal". Defaults to 9999, for which (n_sim + 1) a is a whole number at every tail probability a that is a multiple of 1e-4.

Returns:

cb – The value(s) of the upper, lower, or both confidence bound(s) of the selected function at x. A two-sided bound has one row per x holding the [lower, upper] pair.

Return type:

scalar or numpy array

Examples

>>> import numpy as np
>>> from surpyval import Weibull
>>> np.random.seed(1)
>>> x = Weibull.random(30, 10, 3)
>>> model = Weibull.fit(x)
>>> model.cb([5, 10], on="sf")
array([[0.65083522, 0.88949979],
       [0.1629223 , 0.41352719]])
>>> model.cb([5, 10], on="sf", bound="lower")
array([0.67916426, 0.18042915])
covariance() → NDArray

The covariance of the fitted parameters: the distribution’s, in the order of parameter_names, then the limited-failure proportion lfp_p and the zero-inflation fraction f0 where the model has them (a held parameter has a zero row and column); covariance_names names the rows. An offset gamma is held at its estimate and has no row (see covariance_names). The inverse of the observed information at the maximum, carried to the parameters through their transforms; what Wald bounds use. For a fit with weights w it is the robust (sandwich) covariance, while hess_inv stays the inverse Hessian. Use this, not hess_inv, wherever a variance is wanted.

Raises a ValueError where the model has none: one built with from_params, one whose information was singular, or a closed-form fit with no Wald covariance (Uniform).

Examples

>>> import numpy as np
>>> from surpyval import Weibull
>>> np.random.seed(1)
>>> model = Weibull.fit(Weibull.random(100, 10, 3))
>>> np.sqrt(np.diag(model.covariance())).round(4)
array([0.3589, 0.2286])
property covariance_names: list[str]

The names of the rows (and columns) of covariance(), in its order: the distribution’s parameters (parameter_names), then the limited-failure proportion lfp_p for a model fitted with lfp=True, then the zero-inflation fraction f0 for one fitted with zi=True.

A parameter fixed at fit time keeps its row, a row and column of zeros, since it is known. The offset gamma of a model fitted with offset=True is never a row: it is a threshold parameter, whose likelihood is not regular, so the covariance holds it at its estimate (the other parameters’ variances are conditional on it) and param_cb("gamma", method="lr") or method="bootstrap" bounds it instead. Every model has the names, including one whose covariance() raises (a fit by how="MPS", "MSE" or "MPP", or one built with from_params).

Examples

>>> from surpyval import Weibull
>>> x = [10, 12, 15, 17, 20, 25, 31, 40, 52, 60]
>>> model = Weibull.fit(x, c=[0] * 8 + [1, 1], lfp=True)
>>> model.covariance_names
['alpha', 'beta', 'lfp_p']
>>> model.covariance().shape
(3, 3)
cs(x: ArrayLike, given: ArrayLike) → NDArray

The conditional survival of the model; that is, the probability that an item that has survived to given survives a further x:

\[R(x, given) = \frac{R(x + given)}{R(given)} = e^{-(H(x + given) - H(given))}\]

Changed in version 0.22: The time already survived is given (it was X), the name the regression models’ sf_tvc(..., given=) uses.

Changed in version 0.23: X is removed.

Changed in version 0.24: From the cumulative hazard, so finite where sf(given) underflows (#660).

Parameters:

  • x (array like or scalar) – The further durations at which conditional survival is to be calculated.

  • given (array like or scalar) – The value(s) at which it is known the item has survived

Returns:

cs – The conditional survival probability.

Return type:

array

Examples

>>> from surpyval import Weibull
>>> model = Weibull.from_params([10, 3])
>>> model.cs(11, 10)
np.float64(0.00025840046151723767)

Far in the tail, where the survival to given underflows to 0:

>>> model = Weibull.from_params([100, 3])
>>> model.sf(1000)
np.float64(0.0)
>>> round(float(model.cs(1, 1000)), 6)
0.049638

Notes

It is computed from the model’s own cumulative hazard, the second form above, so it stays exact where \(R(given)\) underflows to 0 far in the upper tail. A limited-failure proportion lfp_p, a zero-inflation fraction f0 and an offset gamma all enter it: the never-failing units still count among the survivors at given, and survival to a given before the offset is certain. Where \(H(given)\) is infinite (the model says no unit survives to given) the conditional survival is undefined and nan is returned.

df(x: ArrayLike, continuous: bool = False) → NDArray

The density function for a distribution using the parameters found in the .params attribute.

Parameters:

  • x (array like or scalar) – The values of the random variables at which the density function will be calculated.

  • continuous (bool, optional) – Only matters for a zero-inflated model. If True, return the density of the continuous part alone, p - f0 times the base density at x - gamma, with no point mass at 0: it integrates to p - f0, so it is the one to integrate numerically (a convolution, the trapezoidal rule). Defaults to False, which returns the point mass f0 at exactly 0, as the likelihood uses it.

Returns:

df – The scalar value of the density function of the distribution if a scalar was passed. If an array like object was passed then a numpy array is returned with the value of the density function at each corresponding value in the input array.

Return type:

scalar or numpy array

Examples

>>> from surpyval import Weibull
>>> model = Weibull.from_params([10, 3])
>>> model.df(2)
np.float64(0.01190438297804473)
>>> model.df([1, 2, 3, 4, 5])
array([0.002997  , 0.01190438, 0.02628075, 0.04502424, 0.06618727])

For a zero-inflated model, df(0) is the point mass f0 (a probability, not a density); continuous=True leaves it out:

>>> zi = Weibull.from_params([100, 2], f0=0.1)
>>> zi.df(0.0), zi.df(0.0, continuous=True)
(np.float64(0.1), np.float64(0.0))

Notes

A zero-inflated model is a mixture of a point mass f0 at 0 and a continuous part of mass p - f0. By default df returns the point mass itself at exactly x == 0, since that is the probability an observation at 0 gets in the likelihood. A density integrated over a grid that starts at 0 then counts a spurious f0 * dx / 2 (trapezoidal rule); use continuous=True for that, and add the mass f0 at 0 separately if it is wanted.

diagnose(alpha: float = 0.05, columns: Sequence[str] | None = None, *, n_boot: int | None = None, random_state: Any = None, **options: Any) → Diagnosis

Check the model’s assumptions, fit and influential points, and say what to do about any that fail.

Runs the checks this kind of model calls for (for a Cox model: proportional hazards, the functional form of each continuous covariate, influence and outliers; see Model Diagnostics) and returns a report: d.table, one row per check with its test, statistic, p-value, verdict ("ok", "warn" or "fail") and covariates; d.advice, plain-English remedies that each name the SurPyval feature that applies them; d.plot(), the visual checks (matplotlib is only imported then); d.ok, True if nothing failed; d.raise_if_failed() for pipelines; and d.to_dict().

A test fails when its p-value is below alpha, and warns when it is below 2 * alpha (borderline) or could not be computed. Each row is judged at alpha on its own, so with many rows some fail by chance even when every assumption holds.

Parameters:

  • alpha (float, optional) – The level each test is judged at. Default 0.05.

  • columns (str or list of str, optional) – The covariates to check, named as summary() names them (the DataFrame or formula columns, else coef_0, …); all of them by default. A joint (GLOBAL) test still covers every covariate.

  • n_boot (int, optional) – For the families whose tests resample (a univariate distribution’s bootstrap goodness-of-fit tests): the number of bootstrap refits; None is the family’s default. Other families ignore it.

  • random_state (optional) – The seed of those resamples (SurPyval’s one seed rule: None draws from numpy’s global generator).

  • **options – Options of the model’s family, named in Model Diagnostics: for an accelerated life model, use_stress, the stress the model is to predict at (a number, or one per stress column), whose distance from the tested stresses the report screens. A family refuses an option it does not take.

Returns:

See surpyval.diagnostics.Diagnosis.

Return type:

Diagnosis

Raises:

  • NotImplementedError – For a model whose family’s diagnostics are not built yet, saying what to check it with meanwhile; for an option of the model the checks do not support yet; and for a kind of model the checks do not cover by design (a discrete distribution, a parametric regression with a custom link, …), saying what to use instead.

  • ValueError – For a model the checks cannot be run on (one restored with from_dict, which has no data), saying what to do.

The contour is where the log-likelihood has fallen from its maximum by half the chi-squared critical value with two degrees of freedom:

\[\log L(\theta) = \log L(\hat\theta) - \chi^2_{2, 1 - \alpha}/2, \qquad \chi^2_{2, 1 - \alpha} = -2 \log \alpha.\]

param_cb(name: str, alpha_ci: float = 0.05, bound: str = 'two-sided', method: str | None = None, n_boot: int = 200, random_state: Any = None, n_sim: int = 9999) → NDArray

Method to calculate the confidence bound on a parameter.

Two interval methods are available via method, and "wald" is the default (method=None):

  • "wald" (default) – a symmetric bound from the parameter’s standard error, computed on a scale chosen from the parameter’s support (log for a positive parameter, logit for a probability) so the interval stays valid.

  • "lr" – a profile-likelihood (likelihood-ratio) bound. The interval is the set of values whose profile deviance \(2[\ell(\hat\theta) - \ell_p(\theta)]\) stays below the \(\chi^2_1\) critical value, with the remaining parameters re-optimised at each candidate. It is transformation-invariant, respects the parameter’s boundary, and need not be symmetric about the estimate – usually better small-sample coverage than Wald, and the reliability-engineering default. Aliases: "likelihood", "likelihood-ratio", "profile". The interval is the stretch around the estimate where the deviance stays below the critical value; where it stays below it out to the edge of the parameter’s space (levelling off there, as a NegativeBinomial’s r does as the model tends to a Poisson), the bound is that edge: 0, 1 or inf. A side whose bound cannot be found is nan, with a warning. For an offset, limited-failure or zero-inflated model the profile is over every fitted parameter, gamma, lfp_p and f0 included, and each of those is bounded too. lfp_p and f0 have a closed edge (1 and 0, the plain model): a side towards it is the edge itself where the profile deviance there is within the critical value, so a two-sided interval covers a truth on the edge with probability 1 - alpha_ci / 2 and the one-sided bound towards it with 1 - alpha_ci, asymptotically (Self and Liang, 1987; a little more in small samples). The offset’s interval runs up to the first failure where its profile stays below the critical value there (the likelihood is unbounded at that corner for a shape below 1, and the region reaches it). The region then holds every point with a shape below 1, so a side of another parameter towards values that have such points (a Gamma alpha below 1; either side of its beta) is the edge of that parameter’s space.

  • "bootstrap" – the parametric bootstrap, as for cb: the bias-corrected percentile interval of the parameter over n_boot refits to data simulated from the model. It is the one bound on an offset’s gamma, and the one on another parameter of an offset model that includes the offset’s uncertainty (the Wald bound holds it at its estimate, with a warning; #645). A limited-failure or zero-inflated model’s refits are fitted the same way (lfp=, zi=), so lfp_p and f0 have bootstrap bounds too; a refit that puts either on its edge (1, 0) counts there, so the interval reaches the edge when enough refits do. Their intervals are BCa: the bias-corrected percentiles moved by an acceleration from the jackknife (the model refitted without each unit in turn). The refits are by the model’s own method: an MPP, MPS, MSE or MOM fit is refitted the same way (they were refitted by maximum likelihood before).

  • "pivotal" – for a probability-plotting fit (how="MPP") of the Weibull, LogNormal, LogLogistic, Normal, Logistic, Gumbel, GumbelLEV or Exponential: the Monte Carlo pivotal bound, from the fits of n_sim standard samples of the same size and rank pattern by the same regression. Exact for complete and type II censored samples, up to Monte Carlo error; approximate with other censoring.

The probability p of a Bernoulli, FixedEventProbability or Binomial fit is bounded from its event and trial counts instead, and there the default is "exact", the Clopper-Pearson interval (as R’s binom.test and scipy’s binomtest), which holds its level at any sample size and gives the zero-failure (success-run) bound; "wald" (on the logit scale) and "lr" are the options (see Bernoulli.fit).

A parameter fixed at fit time is known, so both methods give the degenerate interval at its value. A Wald bound does not exist where the parameter’s variance (from the inverse observed information) is negative – the information is not positive definite, typically because the estimate is at or near a boundary of the parameter space – or where the estimate is on the edge of its support: it is nan there, with a warning saying why.

Parameters:

  • name (str) – The parameter, by name (e.g. "alpha"; "lfp_p" for a limited-failure model, "f0" for a zero-inflated one). A distribution parameter named p (Geometric, NegativeBinomial) is that parameter; the proportion, "p" before v0.23, is "lfp_p" (#608). The offset "gamma" has the likelihood-ratio and bootstrap bounds, not a Wald one: it is a threshold parameter, whose likelihood is not regular, so no standard error is estimated for it.

  • alpha_ci (float, optional) – The significance level: 0.05 (the default) gives a 95% bound.

  • bound (str, optional) – "two-sided" (the default), "upper" or "lower".

  • method (str, optional) – "wald" (the default), "lr", "bootstrap" or "pivotal", as above; "exact" (the default), "wald" or "lr" for the probability models.

  • n_boot (int, optional) – The number of bootstrap refits, with method="bootstrap". Defaults to 200.

  • random_state (int or numpy Generator, optional) – The seed of the bootstrap’s or the pivotal bound’s simulations.

  • n_sim (int, optional) – The number of simulated fits, with method="pivotal". Defaults to 9999, for which (n_sim + 1) a is a whole number at every tail probability a that is a multiple of 1e-4.

Returns:

[lower, upper] for a two-sided bound, else the one bound.

Return type:

numpy array

property parameter_bounds: list[tuple[float | None, float | None]]

one (low, high) pair per entry of the vector with_params() takes, in the order of covariance_names (None for an end with no bound).

A parameter set drawn inside these ranges is one with_params does not refuse for being out of range, and one just outside a finite end is refused. rba(basis: str = 'median') → Parametric

The fit with Abernethy’s reduced bias adjustment (RBA): a small-sample correction of the Weibull shape, or of the LogNormal or Normal sigma, of a maximum-likelihood fit. Opt-in; the fit itself is never changed.

In plain words: with few failures, the maximum-likelihood Weibull shape comes out too large more often than too small (with 5 failures, a true shape of 2 is estimated above 2 about two times in three), and the (log)normal sigma comes out too small. The adjustment shrinks the shape (or stretches sigma) by a factor that depends only on the number of failures r and tends to 1 as r grows, so that the estimate is as often above the truth as below it (basis="median", the RBA), or right on average (basis="mean"). It moves the point estimate only; it is not a bound, and it removes a bias of the estimate, not its spread.

With \(C_4(r) = \sqrt{2 / (r - 1)}\,\Gamma(r / 2) / \Gamma((r - 1) / 2)\), the Weibull shape is multiplied by \(C_4^{3.5}\) (median basis) or \(C_4^{6}\) (mean basis), and the (log)normal sigma by \(\sqrt{r / (r - 1)} / C_4\) (which makes a complete sample’s sigma the mean-unbiased \(s / C_4\)); the other parameter is kept. r counts the units that were not right censored. These are R WeibullR’s rba factors and its "mle-rba" fit, which applies them to maximum-likelihood fits only, as here (Abernethy, The New Weibull Handbook, 5th ed., chapter 5); the factors are exact for any r (WeibullR returns 1 above 343 failures).

Parameters:

basis ({'median', 'mean'}, optional) – For the Weibull shape: "median" (the default, Abernethy’s RBA) or "mean". The (log)normal sigma has one adjustment.

Returns:

The distribution at the adjusted parameters, built as with_params() builds a model (no data or covariance, so no bounds of its own: bound the fit itself), with bias_adjustment saying what was applied.

Return type:

Parametric

Raises:

ValueError – For a fit that is not a plain two-parameter maximum-likelihood fit of the Weibull, LogNormal or Normal (an offset, lfp, zi, weights, truncation, a fixed shape), or with fewer than 3 failures: the message says what to use instead.

rescale_time(factor: float, *, unit: Any = None) → Parametric

Use it to put a life in operating time on the calendar (a unit that operates a quarter of the time ages a quarter of an hour in each hour: factor=0.25), or to change the unit of time (a life in hours, in days: factor=24). The model is the one a fit to the data in the new unit gives (principle 6), found without refitting: each parameter that is a time is divided by factor (a scale, a location, an end of the support, the offset gamma), a rate is multiplied by it, the log of a time (the LogNormal’s mu) less log(factor), and a shape, lfp_p and f0 are kept.

Everything a fit has comes across: its covariance and inverse Hessian by the delta method (exact, as each parameter moves by an affine map of itself), so the standard errors of the shapes are unchanged and those of the times divided by factor; its data in the new unit, so the likelihood-ratio, bootstrap and pivotal bounds are a refit’s; its maximum, how it was fitted and its log-likelihood, which rises by log(factor) for each exact observation (a density per unit of time) and is otherwise a probability, unchanged.

Returns:

A model of the same distribution, with the same offset, limited-failure proportion and zero inflation.

Return type:

Parametric

rmst(tau: float | None = None, alpha_ci: float = 0.05) → dict

Restricted mean survival time up to tau with inference: the expected time a unit lives within the first tau of its life, as the non-parametric models’ rmst gives it from their curve.

It is the area under the fitted survival function from 0 to tau,

\[\mu(\tau) = \int_0^\tau S(t)\, dt = E[\min(T, \tau)],\]

in closed form for the Exponential, \((1 - e^{-\lambda\tau}) / \lambda\), the Weibull, \(\alpha\, \Gamma(1 + 1/\beta)\, P(1/\beta, (\tau/\alpha)^\beta)\) (\(P\) the regularised lower incomplete gamma function), the Gamma and the LogNormal, and otherwise by adaptive quadrature of sf(). An offset (gamma) adds the time before it, where nothing fails; a limited failure population (lfp_p < 1) adds \((1 - p)\tau\) for the units that never fail (so its RMST is finite while its mean is not); zero inflation takes the mass at 0 out. For a distribution on the whole line it is still the area from 0, the time lived in \([0, \tau]\).

The standard error is the delta method’s, \(\sqrt{g^\top \Sigma g}\) with \(g\) the gradient of \(\mu(\tau)\) in the parameters (central differences) and \(\Sigma\) the parameters’ covariance() (the inverse observed information; the robust one for a weighted fit). The interval is that Wald bound on the logit of \(\mu(\tau)/\tau\), so it stays inside \((0, \tau)\): rmst_cb() with method="wald", which also has the likelihood-ratio and bootstrap bounds.

Parameters:

  • tau (scalar, optional) – The horizon. Defaults to the largest observed time, as for the non-parametric models; a model with no data needs it. Unlike theirs, a tau past the data is allowed: the fitted distribution extrapolates.

  • alpha_ci (scalar, optional) – Significance level for the interval (default 0.05).

Returns:

{"rmst", "se", "lower", "upper", "tau"}, as the non-parametric models’ rmst.

Return type:

dict

Raises:

ValueError – Where the model has no bounds (not fitted by MLE, or no covariance): mean(tau=tau) gives the point estimate. Also for a discrete distribution, and for a negative or infinite tau.

Parameters:

Returns:

Examples

>>> from surpyval import Weibull
>>> model = Weibull.from_params([10, 3])
>>> model.var()
np.float64(10.533288486847923)

Notes

For a zero-inflated model (p = 1) this is the variance of the mixture, the mass f0 sitting at 0. For a limited-failure model it is infinite, unless defective=True, which scores the never-failing fraction 1 - p at 0 as well (the defective convention of mean() and moment()). With \(q = p - f_0\) the proportion failing through the base distribution \(X\) (offset by \(\gamma\)), both are

\[\mathrm{Var}(T) = q\,\mathrm{Var}(X) + q(1 - q)\left(\gamma + \mathbb{E}[X]\right)^2,\]

which reduces to \(\mathrm{Var}(X)\) for a plain model (the offset does not change a variance). The defective variance of a limited-failure model is not a variance conditional on failure (fit without lfp for that).

its covariance is then the robust (sandwich) one, its bootstrap bounds the case bootstrap, and the likelihood-ratio bounds and the information criteria refuse.

with_params(params: ArrayLike, gamma: float | None = None, *, lfp_p: float | None = None, f0: float | None = None, hr: float | None = None) → Parametric

The same model with other parameters.

The distribution, its unit, and which of the offset gamma, limited-failure proportion lfp_p and zero-inflation fraction f0 it has are kept; their values are kept too (see extras) unless given. Use it to perturb or redraw a fitted model’s parameters: a parameter vector drawn from covariance() (in the order of covariance_names) maps straight back to a model, so the fit’s uncertainty can be carried into anything built from it. from_params(model.params) alone silently drops the offset, lfp_p and f0.

Parameters:

  • params (array like) – Either the distribution’s parameters (in the order of model.dist.parameter_names), or every parameter of covariance() in the order of covariance_names: the distribution’s, then lfp_p and f0 where the model has them, fixed ones included – the vector a draw from the covariance gives (model._estimates() is the fit’s). They are checked as from_params checks them.

  • gamma (float, optional) – The offset, for a model with one (it is not in the covariance, so not in params). Without it the model’s own is kept. A model without an offset refuses it: build one with model.dist.from_params(params, gamma=...).

  • lfp_p (float, optional) – The limited-failure proportion, with the distribution’s parameters alone (as MixtureModel.with_params takes w); with the full vector it is the vector’s.

  • f0 (float, optional) – The zero-inflation fraction, likewise.

  • hr (float, optional) – The hazard ratio, which any model may be given (it is known, not estimated, so it is never in params). Without it the model’s own is kept.

Returns:

A model built from parameters, as from_params builds it: it has no data, covariance or fitted likelihood, since those belong to the fit of the original parameters, so data-based methods (plot, confidence bounds, aic) are not available on it. A model fitted with weights w gives just the distribution at the new parameters (no data, so no weights).

Return type:

Parametric

Raises:

ValueError – Where params has neither length, where a keyword names a parameter the model does not have or one params already holds, or where a value is outside its range (an lfp_p above 1 or an f0 below 0, as a draw near an edge can be): the message says what to do.

Examples

>>> from surpyval import Weibull
>>> model = Weibull.from_params([100, 2], gamma=5.0, lfp_p=0.9, f0=0.1)
>>> other = model.with_params([120, 2])
>>> other.params, other.gamma, other.lfp_p, other.f0
(array([120,   2]), 5.0, 0.9, 0.1)

The full vector, in the order of covariance_names, and a new offset:

>>> model.covariance_names
['alpha', 'beta', 'lfp_p', 'f0']
>>> other = model.with_params([120, 2, 0.8, 0.05], gamma=4.0)
>>> other.gamma, other.lfp_p, other.f0
(4.0, 0.8, 0.05)

A fit’s uncertainty carried forward, by draws from its covariance:

>>> import numpy as np
>>> x = [10, 12, 15, 17, 20, 25, 31, 40, 52, 60]
>>> fit = Weibull.fit(x)
>>> rng = np.random.default_rng(1)
>>> draws = rng.multivariate_normal(fit.params, fit.covariance(), 500)
>>> sf20 = [fit.with_params(d).sf(20.0) for d in draws]
>>> round(float(np.std(sf20)), 2)
0.12
