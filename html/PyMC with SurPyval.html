PyMC with SurPyval

If you already build Bayesian models in PyMC, surpyval.pymc lets you use SurPyval’s handling of lifetime data inside them. You write the model as usual – your priors, your hierarchy, your sampler settings – and one call adds the likelihood of your data: every failure, survivor, inspection interval and truncation window, counted exactly as SurPyval’s fit counts them.

In plain words: a censored or truncated lifetime is not an ordinary data point, so it cannot go into observed= of a PyMC distribution. A unit still running at 3,000 hours tells you only that its life is longer than 3,000 hours; a unit found failed at an inspection tells you only that it failed between two inspections; a unit you only heard about because it survived to 1,000 hours is from a population cut off at 1,000 hours. Each needs its own term in the likelihood. censored_likelihood writes those terms for you.

SurPyval does not install PyMC and does not depend on it. import surpyval never imports it. The helpers import it when you call them, and if it is not installed they stop with a message saying to install it (pip install pymc).

The helpers are:

  • censored_likelihood(): add the likelihood of a data set to the open model, as a pm.Potential;

  • log_likelihood(): the same term as a pytensor expression, to combine yourself;

  • prior_from_model(): a prior from a SurPyval fit (last year’s data, another fleet), keeping its uncertainty;

  • prior_from_spec(): priors from a plain description that can be stored as JSON;

  • to_surpyval(): the posterior draws back into a SurPyval model, with its functions, credible intervals and plots.

They support the Weibull, Exponential, LogNormal, Gamma, LogLogistic, Normal, Gumbel, Logistic and Rayleigh distributions (surpyval.pymc.SUPPORTED); any other is refused with that list.

From an old fleet to a new design

A fleet of pumps of an old design has years of records, and a new design has a handful. The question is the new design’s B10 life. With six records, the new design’s shape parameter is barely known; the old fleet’s is. A hierarchical model lets the two designs share the shape and pull their scales towards a common value, so the new design borrows strength from the old without being forced to be the same.

The old fleet’s records are of every kind: failures, pumps still running, pumps found failed at an inspection (an interval), and pumps that were already in service when records began at 2,000 hours (left truncated: pumps that failed before then never made it into the records).

import numpy as np
import pymc as pm
import surpyval as sp
from surpyval.pymc import censored_likelihood

# The old design: x is a time, or [lower, upper] for an interval;
# c is 0 failed, 1 still running, 2 failed between the two times;
# n counts identical rows; tl is when each pump entered the records.
old = sp.SurpyvalData(
    x=[12_400, 15_900, [17_000, 21_000], 19_800, 22_000, 24_500,
       [9_000, 13_000], 26_000, 8_700, 30_000],
    c=[0, 0, 2, 0, 1, 0, 2, 1, 0, 1],
    n=[1, 2, 3, 1, 9, 1, 2, 6, 1, 14],
    tl=[2_000, 2_000, 2_000, 0, 0, 2_000, 0, 2_000, 0, 2_000],
)

# The new design: three failures and three pumps still running.
x_new = np.array([6_100, 9_800, 11_500, 8_000, 10_000, 12_000])
c_new = np.array([0, 0, 0, 1, 1, 1])

with pm.Model() as model:
    beta = pm.LogNormal("beta", mu=0.8, sigma=0.3)  # shared shape
    mu = pm.Normal("mu", mu=9.8, sigma=1.0)         # typical log scale
    tau = pm.HalfNormal("tau", sigma=0.5)           # how far designs differ
    z = pm.Normal("z", mu=0.0, sigma=1.0, shape=2)  # non-centred
    log_alpha = pm.Deterministic("log_alpha", mu + tau * z)

    censored_likelihood(sp.Weibull, old, name="old",
                        alpha=pm.math.exp(log_alpha[0]), beta=beta)
    censored_likelihood(sp.Weibull, x=x_new, c=c_new, name="new",
                        alpha=pm.math.exp(log_alpha[1]), beta=beta)

    trace = pm.sample(target_accept=0.95, random_seed=1)

Everything else is ordinary PyMC and ArviZ: az.summary(trace), az.plot_trace(trace), pm.find_MAP(). (The scales are written non-centred, mu + tau * z, as usual for a hierarchy with few groups: the centred form gives divergences here.) The B10 of the new design, for each posterior draw, is the Weibull quantile at 0.1:

alpha_new = np.exp(trace.posterior["log_alpha"].values[..., 1]).ravel()
beta_draws = trace.posterior["beta"].values.ravel()
b10 = alpha_new * (-np.log(0.9)) ** (1 / beta_draws)
np.percentile(b10, [5, 50, 95])   # a 90% credible interval and median

In one run with PyMC 6.3 this gave a median B10 of about 5,900 hours, with a 90% credible interval of about 3,300 to 11,600 hours: wide, as six records of a new design should leave it, with the shape borrowed from the old fleet. (These numbers are illustrative: PyMC is not installed when the documentation is built, so the code on this page is not run, and another sampler version or seed gives slightly different draws.)

To use the posterior as a SurPyval model, turn the trace back into one with to_surpyval(), naming the variable that holds each parameter (with an index for an element of a vector) and how to get from it to the parameter:

from surpyval.pymc import to_surpyval

new_design = to_surpyval(trace, sp.Weibull,
                         alpha="log_alpha[1]", transform={"alpha": "exp"},
                         beta="beta", data=(x_new, c_new))
new_design.quantile_cri(0.10)   # the B10's credible interval
new_design.sf(10_000)           # the chance a new pump survives 10,000 h
new_design.plot()               # its data, the curve and its band

The result is a BayesianParametric, the same model fit_bayes returns: its sf, ff, qf and mean are those of a new unit with the uncertainty in the parameters averaged in, and cri, quantile_cri, mean_cri and param_cri give credible intervals. A parameter left out is the variable of its own name; a transform is "exp", "log", "inverse" or a function of the draws. Draws outside a parameter’s bounds (a log scale passed without transform={"alpha": "exp"}) are refused.

The data can be a SurpyvalData (from arrays, from_items, from_dataframe …) or the arrays themselves, in any of the forms fit takes: x, c, n with t or tl and tr, or xl and xr for intervals. They are checked exactly as fit checks them, so a mistake (a censoring flag of 3, a time outside its truncation window, a negative time for a Weibull) is refused with the same message fit gives.

What each row adds

Each row adds one term to the log-likelihood, multiplied by its count n. Writing \(f\) for the density, \(F\) for the CDF and \(S = 1 - F\) for the survival function:

row

term

failure at x (c=0)

\(\log f(x)\)

running at x (c=1)

\(\log S(x)\)

failed before x (c=-1)

\(\log F(x)\)

failed in [xl, xr] (c=2)

\(\log[F(x_r) - F(x_l)]\)

seen only in (tl, tr]

minus \(\log[F(t_r) - F(t_l)]\)

A truncation window is the condition for a row to be in the data at all, so its probability divides every row it applies to. A censored row with a truncation bound on its censored side becomes an interval ending at that bound (a pump running at 9,000 hours in a study that ends at 10,000 can only have failed between the two), as in fit.

The terms are written in the stable forms SurPyval uses itself, so they stay accurate far into the tails: \(\log F\) of a Weibull is \(\log(1 - e^{-H})\) computed without cancellation, a window whose lower end is in the upper tail is taken from the survival function (\(\log S(t_l) + \log(1 - S(t_r) / S(t_l))\)), and the normal tails use the scaled complementary error function. At fixed parameters the term equals SurPyval’s own log-likelihood to 1e-10 or better, for every family, row type and truncation pattern, and its gradient, which PyMC’s samplers use, matches a numerical derivative of SurPyval’s (both are tested).

The term is a pm.Potential. It counts in pm.sample and pm.find_MAP as an observed variable would, but, like any potential, it is not drawn by the prior or posterior predictive samplers and is not in the log_likelihood group that LOO and WAIC read.

Covariates

A parameter can be one value for every row, or one value per row. Per-row values give each row its own distribution, which is how covariates enter:

Z = np.column_stack([load, temperature])   # one row per data row
with pm.Model():
    b0 = pm.Normal("b0", mu=9.0, sigma=2.0)
    b = pm.Normal("b", mu=0.0, sigma=1.0, shape=2)
    beta = pm.LogNormal("beta", mu=0.5, sigma=0.5)
    # A Weibull accelerated-failure-time model: log(alpha) linear in Z
    censored_likelihood(sp.Weibull, x=x, c=c, tl=tl,
                        alpha=pm.math.exp(b0 + Z @ b), beta=beta)

The rules:

  • a parameter is a number, a PyMC variable or a pytensor expression, of shape () (every row) or (len(data),) (one per row); anything else is refused;

  • per-row values follow the data’s rows in order. Arrays passed as x, c, … keep the order you give them. A SurpyvalData built from arrays without covariates merges identical rows and sorts them, so for per-row values pass the arrays, or build the SurpyvalData with Z= (which keeps the order) and use data.Z;

  • a length that is only known when the model runs is checked then.

Priors from SurPyval

prior_from_model turns a fitted SurPyval model into a joint prior: a multivariate normal on the log of each positive parameter (a real-line parameter as it is), centred on the fit’s estimates with its covariance. It keeps how sure the old fit was, and how its parameters moved together. weight counts the old fit as a share of its information: weight=0.5 doubles its covariance, for data only partly like the new.

from surpyval.pymc import prior_from_model, prior_from_spec

last_year = sp.Weibull.fit(x_2025, c_2025)
with pm.Model():
    prior = prior_from_model(last_year, name="fleet", weight=0.5)
    censored_likelihood(sp.Weibull, x=x_2026, c=c_2026, **prior)
    trace = pm.sample(random_seed=1)

The variables are fleet_z (the unconstrained vector) and fleet_alpha, fleet_beta. A model with no covariance (one built with from_params) is refused; say how sure you are with prior_from_spec instead.

prior_from_spec builds independent priors from a description of each parameter’s prior: a SurPyval distribution, or the same as a tuple or a dict, which can be stored as JSON. The parameters are SurPyval’s, in SurPyval’s order, whatever PyMC calls them (a Weibull prior is (scale, shape), a Gamma prior’s second parameter is its rate):

with pm.Model():
    prior = prior_from_spec(
        {"alpha": ("lognormal", 9.0, 1.0),
         "beta": sp.LogNormal.from_params([0.8, 0.3])},
        dist=sp.Weibull,
    )
    censored_likelihood(sp.Weibull, x=x, c=c, **prior)

With dist given, every name must be one of its parameters, and a prior that puts mass below zero on a positive parameter (a Normal on a Weibull shape) is refused. The priors it builds are Normal, LogNormal, Gamma, Weibull, Exponential, Uniform, Beta and Logistic.

API

surpyval.pymc.censored_likelihood(dist: Any, data: Any = None, *, name: str = 'likelihood', x: Any = None, c: Any = None, n: Any = None, t: Any = None, xl: Any = None, xr: Any = None, tl: Any = None, tr: Any = None, **params: Any) → Any

Add SurPyval’s censored and truncated likelihood of the data to the open PyMC model, as a pm.Potential called name.

The term is log_likelihood(): every row type SurPyval fits (failures, right, left and interval censoring, left and right truncation, counts) with the distribution’s own stable formulas. The parameters are anything PyMC can build on: random variables, expressions of them (pm.math.exp(log_alpha[0])), or numbers.

Parameters:

  • dist (distribution) – One of SUPPORTED, such as surpyval.Weibull.

  • data (SurpyvalData or array-like, optional) – The data; an array is taken as x.

  • name (str, default "likelihood") – The name of the Potential in the model; give each data set its own.

  • x (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • c (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • n (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • t (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • xl (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • xr (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • tl (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • tr (array-like, optional) – The data as arrays in SurPyval’s usual forms, checked as fit checks them, and kept in the order given.

  • **params – Every parameter of dist by name: a scalar applies to every row, a vector of one value per row (len(data), in the data’s row order) gives each row its own, as with covariates (alpha=pm.math.exp(Z @ b)).

Returns:

The Potential. It counts in sampling and in pm.find_MAP, as an observed variable would; like any Potential it is not drawn by pm.sample_prior_predictive or sample_posterior_predictive and is not in the log_likelihood group LOO and WAIC read.

Return type:

TensorVariable

Examples

>>> import pytest; pm = pytest.importorskip("pymc")
>>> import surpyval as sp
>>> from surpyval.pymc import censored_likelihood
>>> with pm.Model() as m:
...     beta = pm.LogNormal("beta", mu=0.5, sigma=0.5)
...     alpha = pm.LogNormal("alpha", mu=3.0, sigma=1.0)
...     term = censored_likelihood(
...         sp.Weibull, x=[12, 18, 25, 30], c=[0, 0, 1, 1],
...         alpha=alpha, beta=beta, name="tests")
>>> [p.name for p in m.potentials]
['tests']
surpyval.pymc.log_likelihood(dist: Any, data: Any = None, *, x: Any = None, c: Any = None, n: Any = None, t: Any = None, xl: Any = None, xr: Any = None, tl: Any = None, tr: Any = None, **params: Any) → Any

SurPyval’s log-likelihood of the data as a pytensor expression of the parameters, the term censored_likelihood() adds to a model.

Each row contributes its own term, times its count n: log f(x) for a failure (c = 0), log S(x) right censored (c = 1), log F(x) left censored (c = -1) and log[F(xr) - F(xl)] interval censored (c = 2); a row observed only inside the window (tl, tr] subtracts log[F(tr) - F(tl)]. A censored row with a finite truncation bound on its censored side is an interval ending at that bound, as in fit. This is the likelihood fit maximises, equal to the distribution’s to rounding.

Parameters:

  • dist (distribution) – One of SUPPORTED, such as surpyval.Weibull.

  • data (SurpyvalData or array-like, optional) – The data; an array is taken as x.

  • x (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • c (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • n (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • t (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • xl (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • xr (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • tl (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • tr (array-like, optional) – The data as arrays in SurPyval’s usual forms (see Conventions), checked as fit checks them, and kept in the order given.

  • **params – Every parameter of dist by name (alpha=..., beta=...): a number, a PyMC variable or a pytensor expression. A scalar applies to every row; a vector of one value per row (len(data), in the data’s row order) gives each row its own, for covariates.

Returns:

A scalar: the sum of the rows’ terms.

Return type:

TensorVariable

Examples

>>> import pytest; pt = pytest.importorskip("pytensor.tensor")
>>> import surpyval as sp
>>> from surpyval.pymc import log_likelihood
>>> ll = log_likelihood(sp.Weibull, x=[1, 3, [2, 4]], c=[0, 1, 2],
...                     alpha=3.0, beta=1.5)
>>> round(float(ll.eval()), 6)
-3.440673
>>> data = sp.SurpyvalData(x=[1, 3, [2, 4]], c=[0, 1, 2])
>>> round(float(sp.Weibull._log_likelihood(data, 3.0, 1.5, 0, 0, 1)), 6)
-3.440673
surpyval.pymc.prior_from_model(model: Any, name: str | None = None, weight: float = 1.0) → dict

A joint PyMC prior from a fitted SurPyval model: its estimates and covariance, as a multivariate normal on the unconstrained scale (the log of a positive parameter, a real-line parameter as it is).

In plain words: last time’s fit becomes what you believe before the new data, as sure of each parameter as that fit was, and keeping how the parameters moved together. weight discounts it: 0.5 counts the old fit as half as much information (its covariance is divided by 0.5), for data that are only partly like the new.

Parameters:

  • model (Parametric) – A fitted model with a covariance (model.covariance()), such as surpyval.Weibull.fit(x, c); not one with an offset, a limited-failure proportion or zero inflation.

  • name (str, optional) – The prefix of the variables added; default the distribution’s name in lower case ("weibull"). The prior is {name}_z, the unconstrained vector, and {name}_{parameter} each parameter.

  • weight (float, default 1.0) – The share of the old fit’s information to keep, in (0, 1].

Returns:

{parameter: variable}, ready for censored_likelihood() as **prior.

Return type:

dict

Examples

>>> import pytest; pm = pytest.importorskip("pymc")
>>> import surpyval as sp
>>> from surpyval.pymc import prior_from_model
>>> old = sp.Weibull.fit([310, 520, 640, 790, 905, 1100, 1240])
>>> with pm.Model() as m:
...     prior = prior_from_model(old, name="fleet", weight=0.5)
>>> sorted(prior)
['alpha', 'beta']
>>> prior["alpha"].name
'fleet_alpha'
surpyval.pymc.prior_from_spec(spec: Mapping, dist: Any = None, name: str | None = None) → dict

Independent PyMC priors, one per parameter, from a plain description that can be stored as JSON.

Each entry is a SurPyval distribution with its parameters (sp.LogNormal.from_params([0.8, 0.3])), the same as a sequence ("lognormal", 0.8, 0.3), or {"dist": "lognormal", "params": [0.8, 0.3]}. The parameters are SurPyval’s, in SurPyval’s order (a Weibull prior is ("weibull", scale, shape); a Gamma prior’s second parameter is its rate), whatever PyMC calls them.

Parameters:

  • spec (mapping) – {parameter: prior}.

  • dist (distribution, optional) – The distribution the priors are for (surpyval.Weibull): then every name must be one of its parameters, and a prior on a positive parameter must be on positive values.

  • name (str, optional) – A prefix for the variables’ names ({name}_{parameter}); default none, so each variable is named after its parameter.

Returns:

{parameter: variable}.

Return type:

dict

Examples

>>> import pytest; pm = pytest.importorskip("pymc")
>>> import surpyval as sp
>>> from surpyval.pymc import prior_from_spec
>>> with pm.Model() as m:
...     prior = prior_from_spec(
...         {"alpha": ("lognormal", 7.0, 1.0),
...          "beta": sp.LogNormal.from_params([0.8, 0.3])},
...         dist=sp.Weibull)
>>> sorted(v.name for v in m.free_RVs)
['alpha', 'beta']
surpyval.pymc.to_surpyval(trace: Any, dist: Any, *, transform: Mapping | None = None, data: Any = None, priors: Any = None, **param_map: str) → Any

A SurPyval Bayesian model from PyMC’s posterior draws: the distribution with each draw’s parameters, with sf, ff, qf, credible intervals (cri, quantile_cri), plot and the rest of BayesianParametric.

Parameters:

  • trace (InferenceData or MultiTrace) – What pm.sample returned.

  • dist (distribution) – The SurPyval distribution the draws are for, such as surpyval.Weibull.

  • transform (mapping, optional) – {parameter: "exp" | "log" | "inverse" | function}, applied to the draws of a variable that is not the parameter itself (a log scale sampled as log_alpha: transform={"alpha": "exp"}).

  • data (SurpyvalData or array-like, optional) – The data, for plot and compare.

  • priors (optional) – The priors, kept with the model for its summary.

  • **param_map – Each parameter’s variable in the trace, by name, with integer indices for an element of a vector (alpha="log_alpha[1]"); a parameter not given is the variable of its own name.

Returns:

Its diagnostics record the sampler and the variables used.

Return type:

BayesianParametric

Examples

>>> import pytest; az = pytest.importorskip("arviz")
>>> import numpy as np
>>> import surpyval as sp
>>> from surpyval.pymc import to_surpyval
>>> rng = np.random.default_rng(1)
>>> trace = az.from_dict({"posterior": {
...     "log_alpha": rng.normal(np.log(100), 0.05, (2, 1000)),
...     "beta": rng.lognormal(np.log(2), 0.05, (2, 1000))}})
>>> model = to_surpyval(trace, sp.Weibull, alpha="log_alpha",
...                     transform={"alpha": "exp"})
>>> model.params.round(0)
array([100.,   2.])
