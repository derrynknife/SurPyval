# Decisions

Design decisions made while working on the open issues, with the reason for each and where it stands. Newest first.

**Who decided:**
- **maintainer:** chosen in review.
- **principle:** settled by a numbered rule in `docs/Design Principles.rst`.
- **proposed:** made during implementation and not yet confirmed.

**Status:** `done` (built), `open` or `gap` (not built yet), `changed (date)` (the maintainer chose otherwise; the reason points to the decision that replaces it), `closed (date)` (not to be built), `superseded (date)` (replaced by a later fix).

**Before asking the maintainer, check the principles.** If one settles the question, apply it and record it here.

## 2026-11-11

### Several failure modes of a repairable system: bounds, growth, forecasts (11 Nov 2026)

| Decision | By | Reason | Status |
|---|---|---|---|
| The names on `CauseSpecificNHPP` are the single-process ones with the cause as `event` (`cif_cb`, `iif_cb`, `mtbf`, `mtbf_cb`, each the cause's own model's), and `total_` in front for the sum over causes (`total_iif`, `total_mtbf`, `total_cif_cb`, `total_iif_cb`, `total_mtbf_cb`), following the existing `total_cif`. The totals have Wald bounds only: Crow's exact bounds are for one power-law process. | principle 21 | One vocabulary; `total_cif` was already there. | done |
| A total's variance is the sum of the causes' delta-method variances on the natural scale, and its bounds are then formed on the log scale, as each cause's are. | proposed | The causes of a marked Poisson process are fitted to disjoint events, so their estimates are independent; the same scale as the single-process bounds makes a one-cause model's total bounds that cause's (tested), and for constant rates gives exactly the bounds of one HPP fitted to every event (tested by hand). Coverage studied: 0.943 to 0.961 at 95% (seed 403, 1000 replicates). | done |
| `growth()` reads the trend from one parameter of the baseline (`beta` of Crow-AMSAA and Cox-Lewis, `alpha` of Duane) and tests it against its no-trend value (1, 0, 1) with a Wald test on the scale of `param_cb`'s interval (the log of a positive parameter), so `trend` is `"none"` exactly when the interval contains that value. The words are the trend tests' (`"increasing"`, `"decreasing"`, `"none"`), about the intensity; a parameter with no variance gives `"undetermined"`. | proposed | The interval and the test cannot disagree; a likelihood-ratio test would need a constrained refit the intensity fitters do not offer. The share of the total intensity has no bounds yet (a gap). | done |
| `growth()` refuses a model fitted with `dist=HPP`, naming `dist` and the baselines to refit with. | principle 2 | A constant rate has no trend parameter; reporting "none" would present an assumption as a finding. | done |
| Forecasts mirror `surpyval.forecast`: `CauseSpecificNHPP.forecast(age, horizon, n, limit, alpha_ci, event)` returns its `Forecast` for one type or, without `event`, for every type, and `surpyval.forecast(model, ...)` is the latter. The interval is the Poisson one at the fitted intensities; it does not carry parameter uncertainty, as the single-process forecast does not. | proposed | The sum of independent Poisson counts is Poisson, so the total needs nothing new; an interval that carried the fit's uncertainty should be added to every Poisson-process forecast at once, not to this model alone (a gap, said in the docs). No table of every cause in one call: the total's row would need a label that could collide with a cause's. | done |
| `CauseSpecificNHPP.to_dict` now writes each cause's parameter covariance (`"covariances"`, `null` for a fit without a likelihood) and the end of observation (`"end"`); the restored model computes its Wald bounds, `growth()` and `summary()` from them. Both keys are optional on reading, so the schema is unchanged and an older dict loads as before (its bounds refuse with the restored model's message). The single-process `ParametricRecurrenceModel` dict is unchanged, so a restored single-process model still refuses its bounds. | proposed | A saved multi-mode model is of little use without its bounds, and the covariance is all a Wald bound needs. Leaving the single-process format alone keeps this change to one model; saving its covariance too would make the two consistent and is the natural next step (open). | done |
| `LikelihoodInferenceMixin.covariance()` is split into `_covariance_matrix()` (the matrix and whether it was found, no warning) and the public method, which warns as before. | proposed | `to_dict` and the tables report a missing covariance as `null` / `nan` without a warning, and package code must not silence warnings with `catch_warnings`. | done |
### Time-varying covariates in the proportional-intensity models (11 Nov 2026)

| Decision | By | Reason | Status |
|---|---|---|---|
| The fitters take the life regressions' names and shapes unchanged: `fit_tvc(i, xl, xr, c, Z, n=None, ...)`, `fit_tvc_timeline(i, x, Z, c, n=None, ...)`, `fit_tvc_from_df` and `fit_tvc_timeline_from_df`, and the model `cif_tvc(x, Z, xl=None, given=None)`, `iif_tvc(x, Z, xl=None)` and `cb_tvc(x, Z, xl=None, given=None, on="cif", alpha_ci, bound)`, with `Z` a `StepSchedule` or rows with `xl`. | principle 21 | One vocabulary for time-varying covariates; a user who knows `sf_tvc` / `cb_tvc` knows these. | done |
| A repairable item fails many times, so `c` is read on every row: in start-stop rows any row may end in a failure, and in a timeline each row says whether it is a failure (`c = 0`) or not (`c = 1`); an item's first timeline row is its entry and must be `c = 1` (refused otherwise). The life models read a timeline's `c` on the last row only. | proposed | The one place the recurrent shape must differ; refusing a failure on the entry row is clearer than ignoring it (principle 2). | done |
| `n` keeps the meaning it has in the same models' `fit`: the number of failures on a counted row (`c = 2`, somewhere in `(xl, xr]`), and 1 elsewhere (`n > 1` on a `c = 0` or `c = 1` row is refused). It is not the life models' count weight of a row. | proposed | Consistency within the model (the fixed fit refuses `n > 1` on exact rows) won over consistency with the life `fit_tvc`; failures counted per inspection period with a covariate per period is a common shape of such data. The alternative is `n` as a number of identical items. | proposed |
| Supported: delayed entry (a first `xl > 0`), gaps between an item's rows (not at risk), failure-truncated items, counted rows (`c = 2`). Refused, saying what to give instead: `c = -1` (a `c = 2` row over its interval), a missing covariate or time (the row is part of an item's history: principle 3), overlapping rows. Right truncation (`tr`) has no argument. | proposed | Every start-stop row states its own window, so a left-censored count is a `c = 2` row; the right-truncated likelihood (#924) along a covariate path is a separate piece. | done (`tr` a gap) |
| The time-varying fit has its own likelihood (`recurrent/regression/tvc.py`), and shares the search, the verification of the maximum, aliasing and the inference with `fit`: each fitter's search moved, unchanged, into `_maximise` (fits of the existing fixtures and the Rossi data are bit-identical before and after). | principle 12, 13 | One search to keep right; `maximum` is set the same way. | done |
| BIC and AIC_c of a time-varying fit count failures (exact rows and counts), as every recurrent fit; rows are not units, so cutting a row leaves the criteria unchanged. | principle 5 (in spirit), the life `fit_tvc` rule | The likelihood is unchanged by a cut, so the criteria must be. | done |
| `cif_tvc` counts from the time origin and refuses a schedule that starts later, as `sf_tvc`; with `given` it counts from that age (0 at and before it) and the schedule need only start by then. `iif_tvc` at a step is the intensity just after it (a `StepSchedule` segment is `[a, b)`), while a fitted row `(xl, xr]` gives a failure at `xr` the row's covariates: a difference on a set of times of measure zero. `cb_tvc` bounds `on="cif"` or `"iif"` on the log scale by the delta method, as `cif_cb` and `iif_cb`; `given` with `on="iif"` is refused. | proposed | Mirrors #930 and #962 for the life models; "expected failures from here on" is the question asked of a repairable item in service. | done |
| A model fitted by `fit_tvc` keeps no `data` (it has no one covariate row per item) and has `is_tvc`; `residuals`, `cramer_von_mises`, `trend_test`, `diagnose` and `plot` refuse for it with a `ValueError` naming `fit_tvc` and what to use instead. `cif`, `iif`, `cif_cb`, simulation and `mcf` at one fixed covariate vector work as for any model; given a `StepSchedule` the simulation methods and `mcf` refuse, naming `cif_tvc`. A `CovariatePath` is refused by the three path methods (`NotImplementedError`, as the life models' refusals of a family with no path form). `is_tvc` is not saved in `to_dict`: a restored model has no data whichever way it was fitted. | proposed | A refusal is better than a fixed-covariate answer for covariates that changed (principles 2 and 22); each is a documented gap. | gap |
| The DataFrame forms take `Z_cols` only, no `formula`. | proposed | As this model's `fit_from_df`; its predictions do not encode a formula's terms. | gap |
| Found, not changed: Duane's standard errors and bounds move slightly with the time unit (se of `alpha` 0.37272 in months, 0.37159 in hours, on the test's rows), for the fixed fit too: the numerical Hessian behind `covariance()` at a scale `b` of 3e-4. The estimates and the likelihood are unit-free, and Crow-AMSAA's bounds are. Pinned as a strict xfail in `tests/recurrent/test_proportional_intensity_tvc.py`. | proposed | Outside this change (the shared `numerical_hessian`); reported for the maintainer. | open |

### Thread-safe warning checks (7 Nov 2026)

| Decision | By | Reason | Status |
|---|---|---|---|
| Library code does not change the process-wide warning filters to detect a warning. The accelerated life fit's per-level start checks the level's fit directly (`np.errstate` with numpy's "warn" settings made "raise", `quiet_maximum_warnings()`, `model.maximum` in verified/not applicable, finite parameters, Kish effective sample size at least 20 with weights) instead of `filterwarnings("error")`. The weights check keeps a fallback whose only cause was the robust-variance warning, which says nothing about the point estimate; it is kept so that every start is the same as before (the old and new decisions agreed on all 4,521 levels fitted by the accelerated life tests, scenarios and conformance cases, and no warning escaped the new path). | proposed | A filter set in one thread applies to all threads, so a fit made other threads' warnings raise. Dropping the weights fallback would change starts (and possibly the last digits of fits) for weighted data; left for the maintainer. | done |
| `formula_model_matrix` finds unknown categorical levels by reading the data for a fitted spec whose categorical terms each code a column as is, and for a formula without `levels=` (whose levels all come from the data); only a formula naming its levels or a term computed from the data (`C(k + 1)`) still catches `formulaic`'s `DataMismatchWarning` with `catch_warnings`. | proposed | Those terms' values exist only inside `formulaic`, and Python 3.11 has no per-thread warning filters; the remaining case is narrow and only affects `DataMismatchWarning`. | done |

## 2026-11-06

### Competing-risks diagnose(): delayed entry and joint fits (6 Nov 2026)

| Decision | By | Reason | Status |
|---|---|---|---|
| With delayed entry, `diagnose()`'s incidence check on a `ParametricCompetingRisks` model compares with `CompetingRisks.fit(..., tl=)`. When every unit enters after 0 that estimate is conditional on surviving to the earliest entry `s`, so the model's incidence is conditioned the same way, `(CIF_k(t) - CIF_k(s)) / S(s)` with `S` the all-cause survival, and the gap is taken from `s` on. The bootstrap draws each cause's latent time beyond the unit's entry (`qf(F_k(tl) + U (1 - F_k(tl)))`), keeps the earliest, censors as before (the censoring distribution already counts units at risk from entry) and refits every cause with the same `tl`. Data without entry times take exactly the old path (checked bit for bit against dev: draws, gaps and p-values). Right truncation (only possible through `from_fitted`) still leaves the incidence rows uncomputed, saying why. | proposed | The Aalen-Johansen estimate takes `tl` since #1105; the conditioning is what that estimate estimates (as `KaplanMeier` with `tl`), and drawing beyond entry is how the data were sampled. | done |
| Size with delayed entry (`tests/calibration/test_size_parametric_competing_risks_diagnostics.py`, seed 291, 200 replicates, n = 100, each unit entering at U(0, 5) and kept only if still in service then, 49 refits, judged at 10%, MC se 0.021): AD rejected 0.070 (a) and 0.030 (b); incidence 0.110 (a) and 0.045 (b). All within the study's tolerance (0.074). Cause b's incidence and AD are conservative here (b's AD is already the univariate test's conservative case with censoring). | proposed | Seed, size and targets fixed before the run; reported as found. | done |
| `diagnose()` on a `ParametricCompetingRisks` fitted to left- or interval-censored rows (a joint fit) refuses with a `NotImplementedError` of its own: the causes are fitted together and keep no data, and every check needs each failure's exact time; it says to compare distributions by `aic()` and the all-cause `sf` with `Turnbull.fit` of the same windows. No check is run on the joint fit: Cox-Snell residuals for interval-censored rows and an Aalen-Johansen estimate for windows are not straightforward, and the joint fit holds no data to run them on. A model restored with `from_dict` (joint or not) keeps the restored model's message; the distinction is an unsaved `_fitted_jointly` flag set by the joint fit. | proposed | An accurate refusal is better than a check that is not valid; the restored message was wrong for a fitted joint model. | done |
| A joint fit's dict (with its `"joint"` entry: the covariance between causes, `neg_ll`, `k`, `n`) is stamped schema 4, so SurPyval 0.26 and older refuse it with a request to upgrade rather than load it without the terms between causes. Every other `ParametricCompetingRisks` dict is unchanged (schema 1 or 2 as before, loadable by old readers). Supersedes the 5d row "`to_dict` of a joint fit adds an optional `"joint"` entry ... no schema change". | maintainer (2026-11-06) | The same pattern as weighted models (B6): a refusal is better than an older reader silently using a smaller covariance. | done |

### 0.27 WP2b: uncertainty of a fixed probability (5 Nov 2026)

| Decision | By | Reason | Status |
|---|---|---|---|
| A fitted `Bernoulli`, `FixedEventProbability` or `Binomial` has `covariance()` = `p_hat (1 - p_hat) / N` from its event counts (the inverse observed information), and `standard_errors()`. The Binomial's is 2 x 2 over `[n, p]` with a zero row and column for the known `n`, as a held parameter has, rather than 1 x 1. Names come from the base class's `covariance_names` (no per-model attribute). | proposed | Consistency: `covariance()` follows `parameter_names` on every `Parametric`. | done |
| At `k = 0` or `k = N` the variance is `nan`, not 0, and is not a refusal: `covariance()` returns `[[nan]]`, `standard_errors()` `nan`; the docs point to `param_cb("p")`. | proposed | 0 would tell propagation code `p` is known after, say, no failures in 20 demands; the package's Wald bound is already `nan` there, and `standard_errors_of` documents `nan` for a parameter on a boundary. A refusal would need its own message in the base class, which this change does not touch. | done |
| No new `p_cb`: the Jeffreys interval is `param_cb("p", method="jeffreys")`, beside `"exact"`, `"wald"` and `"lr"`. The default stays `"exact"` (Clopper-Pearson). | proposed | `param_cb` already routes these models to bounds from the counts; one entry point. Exact holds its level at every `p` (study: 0.968 to 0.995 at 95%); Jeffreys fell to 0.883 and 0.904 in two cells, and changing the default would move published numbers. | done |
| Jeffreys at `k = 0` / `k = N`: lower 0 / upper 1, with the other bound still at `alpha / 2` (two-sided), as Clopper-Pearson does. R's `binom::binom.confint(methods = "bayes")` moves the whole `alpha` to the open tail there. | proposed | Same convention as the exact interval in the same function; Brown, Cai and DasGupta (2001). | done |
| No `p_random` / posterior draw method on the fitted model. Draws of `p` come from `Bernoulli.fit_bayes(x, priors={"p": Beta.from_params([0.5, 0.5])})`, the conjugate Jeffreys posterior. | proposed | The Bayesian module already gives it (and `draw_models`); `Parametric` has no parameter-draw convention to follow. | done |
| These fits take no `w` (they already raise `WeightedRefusal`); counts go in `n`, so no robust variance is needed. | proposed | No silent wrong variance. | done |

### Parametric competing risks with left- and interval-censored rows (WP5 5d)

| Decision | By | Reason | Status |
|---|---|---|---|
| `ParametricCompetingRisks.fit` takes `c = -1` and `c = 2` rows with their cause. A window `(a, b]` of cause `k` contributes `CIF_k(b) - CIF_k(a)`, a left-censored row the window from its entry `tl` (or the start), each over `S(tl)` with entry.
